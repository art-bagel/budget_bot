# Комиссия при зачислении криптодохода

10.10.2026, ветка `codex/zero-coin-income`.

## Цель

При записи награды / airdrop / стейкинга указать комиссию отдельным полем:
монета и количество из того же кошелька (например, 0.5 GRAM).

## Решение

- Журнал уже умел это: `put__manual_crypto_movement` добавляет команду `fee`
  после основной для любого вида операции, всё в одной транзакции.
- API `POST /portfolio/positions/{id}/income`: в запрос добавлено поле `fee`
  (`ManualCryptoFee`: `source_position_id`, `quantity`), оно передаётся в журнал.
  Для некриптовых позиций `fee` отклоняется с 400.
- Фронтенд: `DefiFeeField` (монеты кошелька с ненулевым остатком, значение
  через `manualFee`) добавлен в обе формы дохода криптопозиции — шторку
  «Зачислить · <монета>» (`CryptoIncomeSheet`, основной путь из карточки монеты)
  и встроенную форму «Доход» в `Portfolio.tsx`.

## Проверки

- `crypto_zero_coin_income.sql`: зачисление с комиссией уменьшает остаток на
  комиссию; комиссия больше остатка отклоняет всё зачисление и ничего не меняет.
  Прогон на dev в транзакции с ROLLBACK; проверено, что тест падает при неверном
  ожидании.

  с комиссией 0.5 GRAM на Main TON: 23.61549262 → 33.11549262 GRAM, события
  `income` и `fee` в одной транзакции.
