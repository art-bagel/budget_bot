## Аудит и воспроизведение

Код: `scripts/crypto/audit_existing_history.py`, `prepare_docker_history.py`,
`finish_docker_history.py`, `test_docker_history.py`; replay получил строго
ограниченный режим `--docker-preview`, без тестового финансирования.

Приватные файлы — `outputs/crypto-docker-migration/`: исходная инвентаризация,
сопоставление, `plan-docker.json`, `state-preview.json`, отчёт
`final-verification.json`, ответы `deployed-api.json`, журналы и дампы.
В каждой перенесённой базе схема `crypto_migration_audit` хранит исходные
заменённые строки, правила исправления и ссылки новых карточных расходов.

Базы локального контейнера:
- `budget_bot` — видимый обновлённый dev;
- `crypto_merge_preview` — проверенная копия перед переключением;
- `crypto_before_20260924` — целиком прежний dev для отката.

Прямое восстановление поверх старой схемы было атомарно отменено из-за
старой сигнатуры SQL-функции. Вместо удаления зависимостей выполнено
транзакционное переключение имён готовой копии и прежней базы. Ни одна из
этих операций не касается production.

Для повторного воспроизведения подготовки нужна свежая копия исходного
дампа в `crypto_merge_preview`. Нельзя повторно «готовить» уже перенесённый
`budget_bot` или запускать isolated funding fixture на реальном владельце.
Старый dev на 5187/8017 остаётся отдельным предыдущим расчётом; актуальный
перенос с исправленными оплатами сервера находится на **8080/8000**.
