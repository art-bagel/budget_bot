# Распознавание чеков по фото

Справочник: как устроено сейчас. Почему именно так и как это делали — в отчёте
[2026-10-31-receipt-scan.md](2026-10-31-receipt-scan.md).

## Что делает

Шторка категории → «Потратить» → «Распознать чек» → фото (камера или
медиатека) → список позиций с русскими названиями → «Подставить». Форма
расхода получает итог (минус удалённые строки), валюту, дату и комментарий со
списком. Списывает только пользователь кнопкой «Списать». В базу распознавание
ничего не пишет, фото нигде не хранится.

## Где код

- [backend/app/services/receipt_scan.py](../backend/app/services/receipt_scan.py)
  содержит промпт, JSON-схему, запрос к модели и строгую очистку ответа (таблица
  исходов — в отчёте, раздел «Решение», п. 1).
- [backend/app/routers/receipts.py](../backend/app/routers/receipts.py) —
  `POST /api/v1/receipts/scan`. Тело — сырой JPEG до 3 МБ. Здесь же проверка флага
  и лимиты.
- [frontend/src/components/ReceiptScanSheet.tsx](../frontend/src/components/ReceiptScanSheet.tsx)
  пережимает фото на canvas (без EXIF, длинная сторона ≤ 2000 px), показывает
  шторку и её состояния.
- [frontend/src/utils/receiptScan.ts](../frontend/src/utils/receiptScan.ts) —
  суммы в `BigInt`, комментарий, дата.

## Провайдер и модель

- aitunnel.ru, OpenAI-совместимый `POST /v1/chat/completions` через `httpx`.
- Модель `claude-haiku-5.5`, режим рассуждений выключен
  (`reasoning: {effort: "none"}`). Константы `RECEIPT_SCAN_MODEL` и
  `RECEIPT_SCAN_API_URL` лежат в [backend/app/config.py](../backend/app/config.py).
- **Сменить модель** — поправить константу и задеплоить. Запасной вариант —
  `qwen3.7-flash`: суммы читает так же, дешевле, но переводит хуже. Сравнение
  моделей — в отчёте.
- Цена Haiku — 0,16–0,29 ₽ за чек (замер 31.10.2026), время — 6–11 с.

## Доступ

1. **Флаг пользователя** `users.receipt_scan_enabled`. По умолчанию выключен, и
   API его не меняет. Без флага кнопки нет, а эндпоинт отвечает 403. Включает
   и выключает владелец прямо в базе (запись в прод — с аппрувом владельца):

   ```sql
   UPDATE budgeting.users SET receipt_scan_enabled = true WHERE id IN (<id>, <id>);
   ```

2. **Ключ** `RECEIPT_SCAN_API_KEY` берётся из секрета GitHub, при деплое попадает в
   `infra/.env`, оттуда в контейнер `api`. Без ключа эндпоинт отвечает 503.
   Нужен отдельный ключ для прода с бюджетом, выставленным в кабинете aitunnel.

## Лимиты

- Одно распознавание за раз на пользователя (второе параллельное получит 429).
- Не больше 20 вызовов модели в час на пользователя. Неудачные вызовы тоже
  считаются, потому что они оплачены. Счётчик хранится в памяти процесса
  (uvicorn работает одним воркером) и обнуляется при рестарте.
- «Отмена» в шторке не останавливает уже начатый вызов модели: он доживает до
  конца и оплачивается.
- Тело запроса — до 3 МБ. В `infra/nginx.conf` для `/api/v1/receipts/` стоит
  `client_max_body_size 4m`, у остального API — 1 МБ по умолчанию.
- Общий таймаут вызова модели — 40 с, меньше `proxy_read_timeout` у nginx (60 с).
- Перед контейнерным nginx стоит Nginx Proxy Manager. Его лимит тела и таймаут
  нужно проверить на проде реальным фото после деплоя (см. отчёт).

## Как выключить

| Как | Когда срабатывает |
|---|---|
| Отозвать ключ в кабинете aitunnel | Сразу; эндпоинт отвечает 502 «Не удалось распознать чек» |
| `UPDATE … receipt_scan_enabled = false` для пользователя | После перезагрузки приложения у него |
| Удалить секрет `RECEIPT_SCAN_API_KEY` в GitHub и перезапустить деплой | После деплоя; без него на хосте остаётся старый `infra/.env` |

## Логи

Пишутся только неудачи, на WARNING (`backend.app.routers.receipts`): `user_id`,
модель, причина (`http 402`, `timeout`, `bad json`…) и длительность. Фото, ответ
модели, текст ошибки валидации и ключ в лог не попадают. Успешные вызовы и
расход видны в статистике ключа в кабинете aitunnel.
