## Все пять ликвидаций

Рубли ниже — подтверждённая часть затрат **в момент соответствующего события**,
в рамках согласованной методики. Само приобретение части монет оценочное;
«подтверждённая часть» означает уже назначенные рубли вместо открытых заёмных
единиц, а не точность банковского документа для каждого исходного рубля.
Позднейшее погашение другого займа может дополнительно уточнять стоимость.

Отдельный штраф **не установлен для всех пяти случаев**. Нулевой технический
параметр не означает доказанный нулевой штраф. Тело/проценты делятся
пропорционально, без отдельной штрафной доли; её уточнение перераспределит
затраты. `minimum_collateral` не используется как размер штрафа.

Это **места назначения на дату каждой проводки**, не сегодняшние остатки и
не уникальные исходные рубли: одна стоимость может участвовать в последующих
погашениях снова. На каждом событии сумма распределения равна стоимости тела.
Рубли и единицы других займов при рефинансировании учитываются раздельно.

не новый денежный расход. Детализация по каждому источнику в локальном отчёте.

## Применение и проверка dev

- `scripts/crypto/audit_history_closure.py` формирует локальную сверку; `--apply`
  обновляет только функцию чтения истории и пояснение в metadata семи позиций.
- Сначала проверочная `crypto_merge_preview`, затем видимая `budget_bot`.
  Точный повтор не меняет пояснения/время обновления повторно.
- Хеш полного журнала до/после одинаковый:
  `b987c1b8b17a20f2289c31d0544f8878721f7accd0a9127b6bc8b3756a2caccb`.
  Финансовые поля позиций и прочие metadata проверены на неизменность.
- Независимый офлайн-декодер подтвердил пять ликвидаций; SQL/HTTP подтвердили
  пять строк тела и семь пояснений, чужой владелец получает отказ.
- TypeScript и Ruff прошли. Lint: 160 прежних warnings / 18 infos, без ошибок.
  Интерфейс собран и развёрнут на **8080**, HTTP 200. API-проверка выполнялась
  внутри запущенного контейнера с временной тестовой идентичностью, без изменения
  авторизации приложения. Браузер показывает вход; личная визуальная приёмка
  карточек не заявляется — она остаётся в R3.3.

Воспроизведение после полного импорта и его финализации:

```sh
python scripts/crypto/audit_history_closure.py --database crypto_merge_preview --apply
python scripts/crypto/audit_history_closure.py --database budget_bot --apply
```

Команды разрешают только названные локальные Docker dev-базы. Перед применением
сохраняются прежние metadata и определение функции. Для отката вернуть только
ключ `historical_accrual_note` из `*-notes-before.json` (или удалить его, если
раньше отсутствовал), восстановить `budget_bot-history-function-before.sql`
и предыдущий образ web. Балансы и проводки откатывать не требуется.
Все персональные отчёты/ответы RPC/логи в `outputs/crypto-r1-audit/`, вне git.
Production не изменён. Следующий крупный блок — R2, ручные операции и исправления.
