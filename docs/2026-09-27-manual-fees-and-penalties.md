# Ручные комиссии и штрафы — 27.09.2026

Ветка `codex/crypto-accounting-recovery`, локальный Docker dev. Production не менялся.

## Выполнено

- В истории монеты у комиссии доступно действие «Записать возврат комиссии»:
  количество, фактическая дата, комментарий. Возвращается пропорциональная
  историческая стоимость и открытые заёмные компоненты, а не доход по курсу.
- Повтор запроса не создаёт дубль. Нельзя вернуть больше исходной комиссии;
  частичные возвраты учитываются совместно. Возврат не может быть раньше расхода.
- Старые общие возвраты без ссылки на комиссию сохранены. Если такой возврат
  уже затрагивает тот же актив/счёт, новый ручной путь требует сверки, чтобы
  не восстановить стоимость дважды. Автоматическая привязка не выдумывается.
- В ликвидации можно отметить «Размер штрафа неизвестен». Общее количество
  изъятого залога сохраняется; распределение стоимости на долг/штраф остаётся
  предварительным. Неизвестный штраф не выдаётся за подтверждённый ноль.
  Для новых команд используется явное поле, старые команды сохраняют трактовку.
- В действующей карточке монеты показаны источник/время котировки;
  устаревшая котировка не используется как текущая оценка.

`crypto_merge_preview` с откатом тестовых изменений. Новые сценарии проверяют
частичные возвраты, стоимость/финансирование, предел суммы, повтор,
предпросмотр исправления и неизвестный штраф ликвидации.
TypeScript, frontend lint, Ruff, сборки API/web и проверка diff пройдены.

`deploy_manual_s3.py --database budget_bot --apply` установил семь функций.
Контрольные отпечатки финансовых таблиц до/после совпали. API и web пересобраны
и перезапущены на dev. Через браузер проверено открытие действия из истории
TON второго кошелька и новой формы; оформление соответствует существующим
полям/нижнему листу, пустой ввод блокирует сохранение. Тестовые финансовые
операции через видимый аккаунт не создавались. Определения прежних функций и результат проверки лежат
в `outputs/crypto-manual-s3/`; миграция — `047_crypto_fee_refunds.sql`.
Для отката кода использовать предыдущие образы и сохранённые определения
функций, предварительно проверив, что после обновления не вводились новые
операции нового вида; такие операции требуют совместимого обработчика.

## Что осталось

R3/S4/R5; единая итоговая сводка R4; согласованный перенос в production R6.

завершение. Полная UI-приёмка не подменяется интеграционными тестами.

Наблюдение для R3: во вкладке «Все» верхний блок показывает криптовалюту
как 0 ₽ при неполной оценке, хотя отдельные монеты имеют котировки; также
остались технические названия пустых счетов. Это не закрыто данным проходом
и должно быть исправлено/проверено в совместной приёмке показателей и экранов.
