# iOS, фаза 1: нативная оболочка

## Цель

Дать приложению иконку на домашнем экране и отвязать повседневное использование
от Telegram. Фаза 0 (собственная авторизация, вход по почте и паролю) закрыта
2026-09-19, см. `2026-09-19-auth-sessions-and-login-methods.md` — без неё
оболочка была бы бесполезна, потому что войти в неё было бы нечем.

Полный нативный клиент не делается сознательно: интерфейс переиспользуется как
есть, нативного кода — около 120 строк.

## Что сделано

1. `.github/workflows/budget_bot_ci_cd.yml` — в триггер добавлен
   `paths-ignore: ['ios/**']`. Без этого каждый коммит в клиент пересобирал и
   передеплоивал прод.
2. `ios/project.yml` — описание проекта для XcodeGen (`brew install xcodegen`).
   Сам `.xcodeproj` не коммитится: `pbxproj` нечитаемо конфликтует при слиянии,
   а из спеки он воспроизводится одной командой.
3. `ios/Budget/` — три файла: `Config.swift` (адрес приложения),
   `WebView.swift` (`WKWebView` и обработка ошибок загрузки),
   `BudgetApp.swift` (точка входа и экран ошибки).
4. `ios/README.md` — сборка под бесплатной подписью и её ограничения.

## Что выяснилось по ходу

- **Xcode на машине не установлен**, есть только Command Line Tools: нет iOS
  SDK, нет симулятора, `xcodebuild` и `simctl` недоступны. Исходники написаны и
  проверены на синтаксис (`swiftc -parse`), но **ни разу не собраны**. Первая
  сборка — за пользователем, после установки Xcode.
- Нативная работа с safe area не понадобилась: фронт отдаёт
  `viewport-fit=cover` и уже считает отступы через `env(safe-area-inset-*)`.
  Со стороны Swift достаточно `contentInsetAdjustmentBehavior = .never`.
- Повторный вход после перезапуска не нужен: хранилище `WKWebView` по умолчанию
  персистентное, `localStorage` с токеном переживает закрытие приложения.
- **Виджеты в эту фазу не попадают.** Бесплатная подписка не даёт App Groups, а
  без общего контейнера расширение WidgetKit не прочитает сессионный токен и не
  сможет обратиться к API. Виджеты и Siri Shortcuts переносятся в фазу 2, после
  оплаты $99/год — это совпадает с изначальным планом.

## Известные уязвимости / осознанные риски

- **Токен сессии лежит в `localStorage` внутри `WKWebView`, а не в Keychain.**
  Комментарий в `frontend/src/session.ts` обещает Keychain в нативной обёртке;
  фаза 1 этого не делает. Хранилище лежит в песочнице приложения и другим
  приложениям недоступно, но не защищено аппаратно и попадает в незашифрованную
  резервную копию устройства. Переносить в Keychain имеет смысл вместе с
  виджетами в фазе 2: там общий контейнер нужен всё равно.
- **`isInspectable = true`** — отладка через Safari Web Inspector. Включено
  только под `#if DEBUG`; для подключения нужен физический кабель и доверенный
  Mac.
- Экран ошибки показывает `error.localizedDescription` как есть. Это системный
  текст сетевой ошибки, пользовательских данных в нём нет.

## Откат

```
git revert <commit>              # оболочка и paths-ignore
rm -rf ios/Budget.xcodeproj      # сгенерированный проект, в git его нет
brew uninstall xcodegen
```

## Открытые вопросы

- Адрес приложения в `ios/Budget/Config.swift` не заполнен — там placeholder
  `https://REPLACE-ME`. До подстановки приложение запускается и показывает
  экран с объяснением вместо падения.
- `index.html` грузит `telegram-web-app.js` с `telegram.org`. В оболочке
  скрипт не нужен, но при заблокированном домене старт ждёт таймаута сети.
  Чинится на стороне фронта: грузить скрипт только внутри Telegram.
- Иконки приложения нет.
