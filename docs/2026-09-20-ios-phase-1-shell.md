# iOS, фаза 1: нативная оболочка

## Цель

Дать приложению иконку на домашнем экране и отвязать повседневное использование
от Telegram. Фаза 0 (собственная авторизация, вход по почте и паролю) закрыта
2026-09-19, см. `2026-09-19-auth-sessions-and-login-methods.md` — без неё
оболочка была бы бесполезна, потому что войти в неё было бы нечем.

Полный нативный клиент не делается сознательно: интерфейс переиспользуется как
есть, нативного кода — около 120 строк.

## Что сделано

1. `.github/workflows/budget_bot_ci_cd.yml` — в триггер добавлен
   `paths-ignore: ['ios/**']`. Без этого каждый коммит в клиент пересобирал и
   передеплоивал прод.
2. `ios/project.yml` — описание проекта для XcodeGen (`brew install xcodegen`).
   Сам `.xcodeproj` не коммитится: `pbxproj` нечитаемо конфликтует при слиянии,
   а из спеки он воспроизводится одной командой.
3. `ios/Budget/` — три файла: `Config.swift` (адрес приложения),
   `WebView.swift` (`WKWebView` и обработка ошибок загрузки),
   `BudgetApp.swift` (точка входа и экран ошибки).
4. `ios/README.md` — сборка под бесплатной подписью и её ограничения.

## Что выяснилось по ходу

- **Xcode сначала отсутствовал** — были только Command Line Tools, без iOS SDK
  и симулятора. После установки Xcode 27.0 понадобились два шага с паролем,
  которые агент выполнить не может: `sudo xcode-select -s /Applications/Xcode.app`
  и принятие лицензии. До этого `xcodebuild` отказывался работать, хотя
  `iPhoneOS27.0.sdk` уже лежал на диске.
- **Сборка и запуск проверены**: `xcodebuild -sdk iphonesimulator` собирается
  без ошибок, приложение установлено на симулятор iPhone 17 и открыло
  `https://budget.mrbagel.ru` — экран входа отрисовался, отступы под Dynamic
  Island корректные. Симулятору подпись не нужна, Apple ID для этой проверки
  не потребовался.
- Нативная работа с safe area не понадобилась: фронт отдаёт
  `viewport-fit=cover` и уже считает отступы через `env(safe-area-inset-*)`.
  Со стороны Swift достаточно `contentInsetAdjustmentBehavior = .never`.
- Повторный вход после перезапуска не нужен: хранилище `WKWebView` по умолчанию
  персистентное, `localStorage` с токеном переживает закрытие приложения.
- **Виджеты в эту фазу не попадают.** Бесплатная подписка не даёт App Groups, а
  без общего контейнера расширение WidgetKit не прочитает сессионный токен и не
  сможет обратиться к API. Виджеты и Siri Shortcuts переносятся в фазу 2, после
  оплаты $99/год — это совпадает с изначальным планом.

## Два бага вёрстки, которые вскрыла оболочка

Вне Telegram `env(safe-area-inset-bottom)` перестаёт быть нулём, и всплыли
два места, где отступ считался дважды. Оба чинятся одной строкой и в Telegram
ничего не меняют, потому что там `env()` = 0.

1. **Метка активной вкладки в нижней навигации.**
   `.bottom-nav` уже добавляет `padding-bottom: calc(6px + env(...))`, а
   `.bottom-nav__item::after` прибавлял `env(...)` ещё раз — жёлтая метка
   уезжала вверх и вставала прямо на иконку. Стало `bottom: 2px`.

2. **Подчёркивание вкладок в настройках.**
   `.st-tabs__ind` позиционируется абсолютно, но без `left`, поэтому точкой
   отсчёта был content-box (уже за `padding-left: 16px`), а JS в
   `Settings.tsx` считает смещение от border-box. Те же 16px попадали в
   расчёт дважды. Добавлен `left: 0`.

Проверено на изолированном стенде в Safari симулятора: у вкладок смещение
линии относительно кнопки было 22px вместо задуманных 6px, после правки —
ровно 6px.

Оба бага задевали и обычный мобильный Safari, просто приложением с телефона
вне Telegram до сих пор никто не пользовался.

## Догоняющие правки того же дня

- **`telegram-web-app.js` больше не грузится безусловно.** Скрипт стоял в
  `index.html` у всех, и нативная оболочка на старте ждала ответа от
  `telegram.org` — от домена, из-за блокировок которого приложение и делалось.
  Теперь `loadTelegramWebApp()` в `frontend/src/telegram.ts` подгружает SDK
  только когда мы действительно внутри Telegram: по параметрам `tgWebApp*` в
  hash, по `TelegramWebviewProxy` нативных клиентов или по признаку фрейма у
  веб-версии. `main.tsx` ждёт загрузки до первого рендера, потому что от SDK
  зависит, показать вход по паролю или пойти по telegram-сценарию.
  Проверено на собранном фронте с двух сторон: без hash скрипт не
  запрашивается и приложение рендерится, с hash — подгружается.
- **Иконка приложения.** Собрана из `frontend/src/assets/logo.png`: альфа
  сведена на белый через `sips` (iOS не принимает прозрачность в иконках),
  кадр подтянут плотнее, чтобы рисунок не тонул в полях.
- **`DEVELOPMENT_TEAM` вынесен в `project.yml`.** Подпись выбиралась в Xcode и
  жила только в сгенерированном `.xcodeproj`, которого нет в git, — каждая
  перегенерация проекта её стирала. Идентификатор не секрет, он есть в любом
  собранном приложении, но привязан к личному Apple ID: при передаче
  репозитория его надо заменить.

## Известные уязвимости / осознанные риски

- **Токен сессии лежит в `localStorage` внутри `WKWebView`, а не в Keychain.**
  Комментарий в `frontend/src/session.ts` обещает Keychain в нативной обёртке;
  фаза 1 этого не делает. Хранилище лежит в песочнице приложения и другим
  приложениям недоступно, но не защищено аппаратно и попадает в незашифрованную
  резервную копию устройства. Переносить в Keychain имеет смысл вместе с
  виджетами в фазе 2: там общий контейнер нужен всё равно.
- **`isInspectable = true`** — отладка через Safari Web Inspector. Включено
  только под `#if DEBUG`; для подключения нужен физический кабель и доверенный
  Mac.
- Экран ошибки показывает `error.localizedDescription` как есть. Это системный
  текст сетевой ошибки, пользовательских данных в нём нет.

## Откат

```
git revert <commit>              # оболочка и paths-ignore
rm -rf ios/Budget.xcodeproj      # сгенерированный проект, в git его нет
brew uninstall xcodegen
```

## Открытые вопросы

- На физическом телефоне приложение ещё не запускалось: подпись бесплатной
  учёткой делается в GUI Xcode под Apple ID пользователя.
- Вход в приложении не проверялся — пароль вводит пользователь сам.
- `index.html` грузит `telegram-web-app.js` с `telegram.org`. В оболочке
  скрипт не нужен, но при заблокированном домене старт ждёт таймаута сети.
  Чинится на стороне фронта: грузить скрипт только внутри Telegram.
- Иконки приложения нет.
