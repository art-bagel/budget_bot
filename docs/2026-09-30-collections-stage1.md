# Коллекции, этап 1: тип счёта и предметы за деньги счёта

30.09.2026, ветка `feat/collections` (от `main` 1c14d6b), коммиты `3eed6fe`,
`afa7ed3`. В production не выкачено.

## Цель

Отдельный тип инвестиционного счёта «Коллекции» для предметов: подарки и
стикеры Telegram, скины CS2, физические коллекционные вещи. У каждого вида свои
параметры. Этап 1 — предметы, купленные и проданные за деньги самого счёта
(рубли, доллары и другие валюты). Крипта на счёте, звёзды, перевод счёта
«Подарки и стикеры», импорт истории, картинки и цены — следующие этапы.

## Что сделано

**База**
- Миграция `052_collectible_investment_asset_type.sql` и `tb/bank_accounts.sql`:
  тип `collectible` в ограничении `chk_bank_accounts_investment_asset_type`.
- `put__create_bank_account`, `get__operations_history`: новый тип в списках.
- `put__create_portfolio_position`:
  - для `collectible` metadata собирается заново из `item_kind` (5 видов),
    `item_link` (только `https://`, до 500 символов) и `item_attributes` (до 20
    текстовых полей по 200 символов); остальные ключи отбрасываются;
  - для **всех** типов ключи `*_in_base` из запроса отбрасываются. Раньше
    `metadata` клиента склеивалась поверх вычисленной себестоимости, и
    `amount_in_base: 1` из запроса подменял её; `realized_result_in_base`
    подмешивался в результат при закрытии. Ни один штатный вызов (форма,
    импорт Тинькофф) такие ключи не передаёт.
- Покупка, продажа, частичная продажа, доплата и комиссия — существующие
  функции позиций, без изменений.

**Бэкенд**: `collectible` в `Literal` моделей `BankAccountItem` и
`CreateBankAccountRequest`.

**Фронтенд**
- `utils/collectibles.ts`: виды и поля (подарок Telegram — коллекция, модель,
  фон, узор, номер; стикер — пак, номер; скин CS2 — оружие, скин, износ,
  паттерн, качество, наклейки; физический — категория, год, состояние, где
  хранится; другое), порядок строк в карточке, безопасная ссылка.
- Настройки и портфель: тип «Коллекции» в выборе типа счёта, вкладка, плитки,
  иконка и цвет.
- Форма предмета: вид, поля вида, ссылка с проверкой https, «Цена покупки»,
  количество 1 по умолчанию, «Дата покупки».
- Список: подзаголовок — вид предмета. Карточка: вид, заполненные поля,
  ссылка (только https, `rel="noopener noreferrer"`).

## Откат

Revert коммитов. Миграцию 052 откатывает возврат прежнего ограничения
(без `collectible`) — только если счетов этого типа нет.

## Известные уязвимости / осознанные риски

- Ссылка на предмет ведёт на внешний сайт: при переходе сайт видит IP и
  User-Agent. Открывается только по нажатию, с `noopener noreferrer`, схемы кроме
  https не отображаются ссылкой и не сохраняются базой.
- Поля предмета — свободный текст пользователя; выводятся как текст React
  (экранируются), в HTML не вставляются.
- Для остальных типов позиций ключи metadata, кроме `*_in_base`, по-прежнему
  принимаются как есть (параметры вклада, тикер и т.п.) — так задумано; новые
  учётные ключи нужно называть с суффиксом `_in_base`.

## Ограничения и открытые вопросы

- Стоимость предмета в оценке равна себестоимости: цен нет до этапа 3.
- Переименование и архив счёта в настройках доступны только криптосчетам;
  исключение из статистики работает для любого счёта.
- Крипта на счёте «Коллекции» — этап 2 (одна общая проверка «счёт может
  держать крипту» вместо 10 копий, тест всех криптоопераций на таком счёте,
  смена типа «Подарков и стикеров», покупка/продажа за монеты, звёзды как монета).
- На dev остался тестовый счёт «Тест коллекций» с закрытой позицией: сделки
  портфеля не отменяются штатно, закрытая позиция и счёт с операциями не
  удаляются. Уйдёт при следующем обновлении dev с прода.
- Dev сейчас работает на контейнерах из `feat/collections`.
