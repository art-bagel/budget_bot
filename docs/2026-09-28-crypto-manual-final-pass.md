## Найденная ошибка и исправление

Закрытие последнего LP сначала завершилось безопасным отказом, без проводок.
Причина — изменяемый тип поля `position_type` у SQL-record в общей функции
ручных движений: после кошельковой операции поле имело тип text, после DeFi —
varchar. PostgreSQL сохранял план выражения в соединении, поэтому результат
зависел от порядка ранее выполненных действий. Перезапуск соединения лишь
маскировал проблему.

Тип позиции вынесен в отдельную переменную text. Регрессия теперь начинает
LP-сценарий с обычной награды на кошелёк на том же соединении: до исправления
падала с DatatypeMismatchError, после прошла. Затем прошли все 28 API/SQL
проверок ручного учёта. Повтор сохранения из ранее отклонённой формы закрыл
LP успешно; история содержит один вывод каждой монеты.

## Интерфейс

- Одноимённые монеты в банковском обмене, свопе, заёме, создании DeFi и награде
  LP различаются по сети и, при совпадении, адресу/сервису. Запись без адреса
  так и обозначена; она не объявляется нативной монетой по одному этому признаку.
- Совпадение сокращений адресов дополнительно различается ID. Балансы и активы
  не объединяются по тикеру. В справочнике проверены ETH и USDT с разной идентичностью.
- Затраты в общей lending-карточке подписаны монетой выбранного залога.
- Убраны оставшиеся постоянные пояснения о правилах общего lending-счёта и
  сохранении стоимости банковского вывода. Оформление и компоненты прежние.

  preview-база, тестовые записи откатываются.
