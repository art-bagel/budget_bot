# Команды main: 171 событие, проверенное через API

## Результат

`compile_main_commands.py` преобразует проверенные исходные действия в шаблоны
штатных команд бота. Для каждого события сверяется сумма команд с фактическим
изменением количества по всем активам. Идентичность jetton задаётся master,
не одним символом. Ресурсы обозначены ссылками на счёт/актив/позицию; перед
проведением они должны быть разрешены в реальные ID.

Из 1049 событий main полностью по количествам сопоставлено 171 событие:

| Команда | Количество |
| --- | ---: |
| Обмен с явно неизвестной исторической RUB-оценкой | 68 |
| Перевод между своими кошельками | 59 |
| Покупка Telegram Stars | 27 |
| Покупка TON за RUB, связанная с main | 12 |
| Продажа другу за RUB | 3 |
| Награда JETTON по воспоминанию владельца | 2 |
| Чистые затраты TON после выделения основных движений | 171 |
| Всего команд | 342 |

15 денежных событий уже входили в прежнюю проверку денежного блока; их нельзя
прибавлять повторно к числу разных разобранных событий.

## Основания и ограничения классификации

- Свои адреса получены из принятых own-wallet-links и перепроверены через общий
  хеш транзакции в событиях main и связанного кошелька. Каждая ссылка сохраняет
  источник. Переход себестоимости выполняется штатной transfer-командой.
- Stars определяются по адресу Fragment и комментарию Telegram Stars вместе.
  Неизвестные переводы не становятся расходами автоматически.
- Денежная операция берётся из уже проверенной связи с main; направление,
  количество и исходный актив сверяются повторно. Не создаётся второй доход.
- Для событий 606 и 664 проверены master JETTON и количества 52/61; сохранена
  степень уверенности OWNER_RECOLLECTION_NOT_DOCUMENTARY_CONFIRMATION.
  Пользовательское предположение не превращается в документальное доказательство.
- Обмены берутся только из успешного JettonSwap main с положительными обоими
  количествами. Старую перенесённую стоимость не используем как цену обмена.
- Отрицательный остаток TON относится на чистые затраты только если все
  экономические действия события уже сопоставлены и других расхождений нет.
  Это чистое уменьшение TON после основных движений, не доказанная детализация
  сетевой комиссии по каждому внутреннему сообщению.
- Положительные необъяснённые остатки не превращаются в бесплатные награды.
  Неизвестные действия, неудавшиеся действия и остатки блокируют всё событие.

Для ещё 27 обменов есть частичные шаблоны, но событие заблокировано из-за
оставшихся действий/движений. `bind_plan_commands` отказывается разрешать
частичное событие. Отсутствующий или невалидный ID ресурса тоже отклоняется.

## API-проверка

Все 171 завершённое по количествам событие проведено через настоящий endpoint
журнала в изолированной PostgreSQL 14 (`boundary_usd_clean`). Для каждого
создан отдельный тестовый пользователь и явно синтетические начальные позиции.
Сверены точные количества по каждому затронутому счёту/активу; неизвестная
стоимость обмена остаётся unknown. Повторный запрос возвращает тот же результат
и не создаёт новых событий портфеля. 8 тестов сборщика и Ruff пройдены.

**Это не непрерывный личный прогон.** Начальные тестовые позиции не являются
восстановленными остатками владельца, их себестоимость не является личным
результатом. Перемежение движений и происхождение финансирования проверяются
в будущем общем прогоне; тест отдельных событий этого не доказывает.
В этом проходе рабочая БД и SQL-правила приложения не менялись.

## Следующий участок

878 событий main остаются заблокированными для генерации полного набора
команд. Это известные события, а не новые вопросы владельцу. Следующий
приоритет — финансирование/возвраты подарочных сервисов как перенос стоимости,
связанные собственные кошельки, затем составные действия и EVAA по принятой
политике. Потребуются общий порядок, реальные начальные источники, безопасное
исправление истории, полный прогон и итоговая сверка интерфейса.
