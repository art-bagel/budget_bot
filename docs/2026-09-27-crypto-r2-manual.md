# R2: ручные операции после импорта — проверка 27.09.2026

Это частичный результат R2, не закрытие всего блока. Изменения применены к
локальным `crypto_merge_preview` и `budget_bot`, API/web Docker dev обновлены.
Продакшен не изменялся.

## Исправлено и проверено

1. Ручной обмен без открытого финансирования переносит списанную историческую
   стоимость на полученную монету. Ранее без рыночной оценки входящая стоимость
   становилась неизвестной. Поле стоимости сделки удалено из формы: рыночная
   оценка не нужна для переноса капитала. Старый параметр API остаётся
   наблюдением и не должен переоценивать капитал. Качество исходной стоимости
   переносится, неизвестная стоимость не превращается в нулевую.
2. Ручная награда передаёт количество строкой, API использует Decimal; сохраняются
   18 знаков. Количество растёт без увеличения затрат и без новых заёмных единиц.
   Запись блокирует позицию, дата операции соответствует дате получения крипты.
3. Расход крипты с банковского счёта передаёт исходное количество строкой,
   API и SQL не округляют его до 12 знаков. Не конечные, неположительные числа
   и количества точнее 18 знаков отклоняются. FIFO стоимость остаётся в копейках.

SQL ручного обмена отличает прямой вызов от журнала по существующему контексту
`budgeting.crypto_source_event_id`: журнал по-прежнему задаёт свою явную политику
и распределяет финансирование. Не следует обходить журнал установкой этого
контекста из публичного API.

## Матрица экран → API → учёт

Наличие формы или API само по себе не означает поддержку согласованной модели.

| Действие | Экран / путь API | Механизм и текущая граница |
|---|---|---|
| Купить через банк | Банковский обмен, затем `/crypto/transfer-to-investment` | Банковские лоты → портфель. Полная пользовательская приёмка в R3 |
| Продать другу | `CryptoWithdrawSheet`, `/crypto/transfer-from-investment`, банковский обмен | Монеты и стоимость выходят в банк; выручка и разница фиксируются банком. Финансируемые выводы имеют ограничения, не обходить их |
| Свой перевод | `CryptoTransferSheet`, `/crypto/transfer-between-investment-accounts` | Общая SQL-функция переносит стоимость; открытые заёмные единицы требуют журнала |
| Обмен | `CryptoSwapSheet`, `/crypto/swap-investment-asset` | В этом проходе исправлен перенос себестоимости. Финансирование на исходной **или целевой** позиции требует журнала |
| Награда | `CryptoIncomeSheet`, `/portfolio/positions/{id}/income` | Нулевая новая стоимость, сохранение заёмных единиц; точность и дата исправлены. Повторное нажатие после сетевой неопределённости пока не защищено ключом идемпотентности |
| Комиссия | DeFi fee → `/crypto/asset-positions/{id}/pay-fee` | Есть API; отдельный вызов после основного действия, ещё не единое атомарное событие интерфейса |
| Банковский расход крипты | `ExpenseDialog`, `/operations/expense` | FIFO списание количества и стоимости; 18 знаков проверены на резерве экскурсии в откатываемом тесте |
| LP вход/пополнение/выход | Формы LP, `/crypto/protocol-positions`, `/top-up`, `/partial-close`, `/close` | Прямые SQL-вызовы. Согласованное распределение по изменению состава реализовано журналом истории; ручную форму ещё нужно связать с ним |
| Стейкинг | Формы протоколов, те же create/top-up/close | Базовые пути есть; конверсия receipt-токена и сохранение финансирования требуют проверки общего журнала |
| Залог | `CryptoLendingActionSheets`, top-up/partial-close/close | Путь есть, финансируемые состояния защищены от прямого обхода журнала |
| Займ | Lending form → take-debt | Для component financing требуется журнал; форма пока не полноценный путь новой модели |
| Проценты | `/accrue-interest`, `/accrue` | SQL/API есть. Текущая форма обновления количества через PATCH не заменяет событие начисления; нужен правильный ручной сценарий |
| Погашение | Lending form → repay-debt | Для распределения погашенной стоимости между держателями нужны команды журнала |
| Ликвидация | `/crypto/protocol-positions/{id}/liquidate` | SQL/API есть; полноценной формы согласованного компонентного учёта нет |
| Историческая поправка | Изменённый source-event отклоняется | Версионирование, сравнение и зависимый replay пока не реализованы. Нельзя объявлять обычное редактирование даты безопасным пересчётом |

## Проверки

`scripts/crypto/test_manual_precision.py`: семь интеграционных проверок на
локальной preview, все финансовые изменения откатываются:

- точные 18 знаков награды, неизменность стоимости/финансирования, дата;
- неверные количества и чужой владелец отклоняются;
- награда → обычный обмен, одинаковая входящая/списанная стоимость;
- неизвестная стоимость остаётся неизвестной даже при переданной рыночной оценке;
- прямой обмен финансируемой позиции отклоняется без изменения остатка;
- обмен финансируемой позиции через журнал работает, повтор не дублирует его;
- банковский расход сохраняет точное количество, сумма FIFO совпадает со стоимостью расхода.

Для проверки снижения средней стоимости добавляется контролируемая стоимость
1000 RUB в откатываемую фикстуру JETTON: выбранный остаток реальной позиции
может состоять только из бесплатных наград. Это не изменение реальной истории.

Frontend typecheck и lint пройдены (160 прежних предупреждений, 18 infos),
Ruff backend/storage и теста пройден. Применение трёх SQL-функций сравнило
отпечатки 13 таблиц финансов и журнала в обеих dev-базах: изменения отсутствуют.
Тестовые операции не оставлены в пользовательском портфеле.
Авторизованный визуальный проход форм ещё относится к R3.3.

Артефакты проверки, прежние определения функций, логи сборки и применения:
`outputs/crypto-r2-manual/` (локально, исключено из git).

## Следующий цельный блок

1. Подключить ручные финансируемые обмены/переводы и lending/LP к журналу:
   стабильный ключ запроса, точные строки, единая транзакция основной операции
   и комиссии, явная политика carry/components. Не менять импортированную историю.
2. Убрать промежуточное Number-преобразование количеств из оставшихся DeFi-форм;
   API чтения пока также отдаёт некоторые количества float: автоподстановка
   полного остатка не даёт гарантии 18 знаков.
3. Реализовать версию исправляемого источника → предварительный пересчёт на
   изолированной копии → сравнение → применение с проверкой неизменности исходной
   версии. В область зависимостей входят банк, FIFO, категории, отложенные расходы
   и операции после среза; локальный reset всего пользователя не является готовым
   пользовательским исправлением.
4. Проверить эту цепочку на dev и только затем закрывать R2.1–R2.3.

## Уточнение Bybit и следующий проход R3 (27.09)

По повторному решению владельца внутренняя торговля Bybit и Earn не являются
пользовательскими операциями. В боте остаются покупки RUB → USDT на банковском
счёте, переводы в реальные кошельки/портфель, возврат в банк и необходимые
банковские расходы. Расчётные источники нужны для стоимости и остаются в журнале.
Удалять их из учёта или заново заводить доход не следует.

Исправлены пять функций чтения: общая история, список счетов, список позиций,
сводка и аналитика портфеля. Основание — существующая метка счёта
`provider_name=reconstruction_internal`, а не поиск слова Bybit в комментариях.
Из ленты исключаются операции, все стороны которых технические. Операции,
затрагивающие обычный банковский счёт или настоящий кошелёк, сохраняются;
техническая сторона не выводится отдельной строкой карточки. Фильтрация до
пагинации сохраняет полные страницы и правильное число операций.

На текущей копии 78 операций скрыты из общей ленты; 389 записей наград
технических счетов исключены из пользовательской аналитики. Внутренние награды
не имели отдельного linked_operation_id и до этого не были 389 строками общей
ленты. Это разные показатели, складывать их как число удалённых операций нельзя.

Проверка `scripts/crypto/check_user_history.py` проходит всю историю:
4831 видимая операция в preview и 4832 в видимом dev, отсутствие дублей по страницам, пять фильтров,
сохранение 4643 операций, затрагивающих обычные счета (включая некриптовалютные),
неизменность сводок обычных счетов, отсутствие технических счетов в списках и
аналитике, отсутствие доступа постороннего пользователя, повтор применения.
Отпечатки 17 таблиц до/после совпадают, включая банковские криптопроводки,
валютные лоты и их списания. Без `--apply` определения функций откатываются.
Проверка и применение разрешены только к двум локальным Docker dev-базам.

Артефакты и прежние определения функций: `outputs/crypto-user-history/`.
Это закрывает часть R3.3 о технических счетах/Bybit, но не ручные сценарии R2,
не визуальную приёмку всех экранов и не весь R3.3.
