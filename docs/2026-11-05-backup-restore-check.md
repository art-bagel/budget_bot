# Проверка восстановления бэкапов и ревизия P1

## Цель

Разобрать P1 бэклога: закрыть пункт про падения деплоя на Docker Hub, если
после перенастройки роутера они ушли, и выяснить состояние бэкапов. Главное —
впервые проверить, что дампы реально восстанавливаются.

Не входит: оповещение о провале бэкапа. Владелец решил 2026-11-05 делать его в
инфраструктурном контуре (`home_network`) для всех сервисов сразу.

## Что нашли

**Деплой.** С 2026-10-18 было 21 запуск CI/CD, все успешны с первой попытки
(`run_attempt = 1`, данные из публичного API GitHub Actions). Пункт закрыт.
Риск «прод наполовину» (сборка образов после миграций) вынесен в бэклог
отдельной задачей.

**Бэкапы, лог `backup-to-minio.log` на хосте 192.168.30.100:**

- локальный контур (MinIO 192.168.30.108) лежал второй раз: с 2026-10-26
  19:15 до 2026-11-04 07:15 UTC — 204 провала подряд, почти 9 суток без
  локального дампа. Ошибки: «Resource requested is unwritable, please reduce
  your request rate», с 02.11 — «Insufficient permissions»;
- 22–25.10 — ещё 8 разовых сбоев «You did not provide the number of bytes
  specified by the Content-Length HTTP header»;
- с 04.11 07:15 локальный снова проходит, ротация до 48 копий работает;
- суточный Selectel успешен все дни.

О простое опять никто не узнал — это аргумент за оповещения в
инфраструктурном контуре.

## Что сделано

Скрипт `scripts/backup-restore-check.sh`. Для каждого контура (`local`,
`remote` или оба):

1. берёт новейший `budget_bot_*.dump` тем же ключом из `infra/.env`, что и
   бэкап;
2. поднимает одноразовый `postgres:17` с `--network none`;
3. делает `pg_restore --exit-on-error`;
4. сравнивает список таблиц и число строк каждой с живой базой.

Печатает только счётчики, данных не выводит. Временный каталог, контейнер и
его том удаляются при выходе. Код ≠ 0 — если дамп не скачался, не
восстановился или набор таблиц отличается. Разница в числе строк — не
ошибка: это то, что записали после дампа.

Запуск на хосте (так прошла проверка 2026-11-04 ~21:45 UTC; скрипт ещё не
задеплоен, поэтому кладётся во временный файл):

```bash
S() { ssh -i ~/.ssh/master_agent_ed25519 master_agent@192.168.30.100 "$@"; }
S 'umask 022; cat > /tmp/budget-bot-restore-check.sh' < scripts/backup-restore-check.sh
S 'sudo -u deploy sh -c "cd /home/deploy/apps/budget_bot && PROJECT_DIR=\$PWD bash /tmp/budget-bot-restore-check.sh"; rm -f /tmp/budget-bot-restore-check.sh'
```

После деплоя — просто `./scripts/backup-restore-check.sh` из каталога проекта
под `deploy`.

|---|---|---|---|---|---|
| local | `20261104T211501Z`, 42 МБ | ok | 44 | 162 817 | нет |
| remote | `20261104T034001Z`, 42 МБ | ok | 44 | 162 511 | 12 таблиц, +1…+224 строки за 18 ч (`fx_rate_snapshots` +224, `crypto_source_mutations` +46, `operations` +5) |

Расхождения remote объясняются возрастом дампа. `current_crypto_balances`
в дампе на одну строку больше — остаток обнулился после 03:40 UTC.

Полный прогон — около 2,5 минуты, на хосте 2 ГБ ОЗУ и 8 ГБ свободного диска.

## Грабли по ходу

- `docker compose` под `deploy` падает с `stat .: permission denied`, если
  текущий каталог — домашний каталог `master_agent`. Запускать из каталога
  проекта.
- Образ `postgres` сначала поднимает временный сервер для инициализации, и
  `pg_isready` по сокету отвечает ему. Через секунду тот выключается, и
  `createdb` получает «the database system is shutting down». Готовность
  проверяется по `-h 127.0.0.1`: временный сервер TCP не слушает.
- `du -h` на ZFS показывает место на диске, а не размер файла (512 байт у
  свежего 42-мегабайтного дампа) — нужен `--apparent-size`.

## Откат

Скрипт только читает: живую базу — `SELECT count(*)`, хранилища — `mc find`
и `mc cp`. Откат — удалить файл из репозитория.

## Открытые вопросы

- Запускать проверку регулярно (cron, например раз в неделю) имеет смысл
  вместе с оповещениями инфраструктурного контура: без канала результат
  никто не увидит, как это уже было с самими бэкапами.
- Почему MinIO отвечал «unwritable» и «Insufficient permissions» — вопрос к
  `home_network`; здесь видна только сторона клиента.

## Известные уязвимости / осознанные риски

- Во время проверки полный дамп прода с реальными финансовыми данными
  несколько минут лежит в `/tmp/budget-bot-restore-check.*` на прод-хосте
  (права `deploy`) и в контейнере без сети. Это тот же хост и та же модель
  доступа, что у самого `backup-to-minio.sh`. Новой поверхности нет.
- Контейнер запускается с `POSTGRES_HOST_AUTH_METHOD=trust`. Допустимо только
  потому, что у него нет сети (`--network none`) и он живёт минуты.
