# Tier 2: вес первого экрана и UX загрузки

Дата: 2026-09-21

## Цель

Из ранжированного разбора проблем проекта взять «Tier 2» — то, что видно
пользователю и чинится дёшево: вес бандла на первом заходе и полноэкранный
сплэш там, где его быть не должно.

Разбор целиком (включая Tier 1, 3, 4) в истории обсуждения; сюда вынесено
только то, что реально сделано.

## Итоговая последовательность

### 1. Логотип: 1.78 МБ → 56 КБ

`frontend/src/assets/logo.png` — PNG 1024×1024 весом 1.78 МБ. Показывается
на 220px (сплэш, `.splash__img`) и 88px (экран входа, `.auth__logo`). Это
был самый тяжёлый файл бандла — тяжелее всего JS — и грузился он первым.

- Пережат в WebP 512×512, quality 85, method 6 → 56 680 байт.
- 512px выбраны как компромисс: ровно @2x под 220px и 2.33x под @3x, на
  декоративной картинке разница неразличима.
- Альфа-канал обязателен: логотип — фигура на прозрачном фоне, JPEG дал бы
  белый квадрат на тёмной теме. Проверено визуально.
- `logo.png` удалён, оба импорта переведены на `logo.webp`.

Иконка приложения iOS (`ios/Budget/Assets.xcassets/.../icon-1024.png`) —
отдельный файл, не затронута.

### 2. nginx: gzip и заголовки безопасности

В образе `nginx:1.27-alpine` сжатие по умолчанию выключено, поэтому бандл
ехал несжатым. Добавлено в `infra/nginx.conf`:

- `gzip on` + `gzip_vary`, `gzip_min_length 1024`, список `gzip_types`
  (текст, JS, CSS, JSON, SVG; растр не трогаем — он уже сжат);
- `X-Content-Type-Options: nosniff` и `Referrer-Policy: no-referrer`.

`X-Frame-Options` **намеренно не добавлен**: Telegram Web открывает Mini App
в iframe, запрет фреймов сломал бы веб-версию Telegram.

Заголовки продублированы в `location = /index.html` и `location /assets/`,
потому что `add_header` в nginx не наследуется в location, где есть свой
`add_header`.

### 3. Сплэш больше не подменяет экран при обновлении данных

Две независимые причины давали один и тот же симптом: после каждого
действия и каждого переключения вкладки вместо контента показывался
полноэкранный `SplashScreen` с ротацией фраз, с потерей скролла и открытых
шитов.

**Причина А — ремонт страницы при навигации.** `App.handleNavigate`
инкрементил `refreshKeys[p]`, а `refreshKeys` стоял в `key` у
`ErrorBoundary`. То есть страница пересоздавалась целиком при каждом
переключении таба — при этом соседняя механика `visited` + `display: none`,
которая существует ровно ради сохранения страницы, полностью обнулялась.

Решение: `refreshKeys` превращён из ключа ремонта в обычный проп
`refreshToken: number`. Страница остаётся смонтированной, а изменение
токена просто перезапускает эффект загрузки.

**Причина Б — `loading` означал сразу две вещи.** Каждый `loadX()`
начинался с `setLoading(true)`, а в рендере стояло
`if (loading) return <SplashScreen />`. Первая загрузка (данных ещё нет) и
фоновое обновление (данные есть) были неразличимы.

Решение: `setLoading(true)` из тела загрузки убран — за первую загрузку
теперь отвечает только начальное значение `useState(true)`. Фоновое
обновление отражает новое состояние `refreshing`.

**Новый компонент `RefreshBar`** — тонкая фиксированная полоса сверху.
Нужна не только для красоты: у pull-to-refresh (`usePullToRefresh`) своего
визуального отклика нет вообще, кроме `navigator.vibrate(15)`, и раньше его
роль играл как раз тот самый сплэш. Без полосы жест стал бы невидимым.
Уважает `prefers-reduced-motion`.

**`ErrorBoundary` получил собственный счётчик ремонта.** Кнопка
«Попробовать снова» раньше работала за счёт внешнего `key` из `App`. Без
него она бы только сбрасывала состояние границы и возвращала то же упавшее
поддерево с его состоянием — то есть падала бы снова на первом рендере.
Теперь дети рендерятся в `<Fragment key={resetCount}>`.

Затронуты: `App.tsx`, `ErrorBoundary.tsx`, новый `RefreshBar.tsx`,
`styles.css`, страницы `Dashboard`, `Exchange`, `Portfolio`, `Credits`,
`Family`, `Settings`.

### 4. Code splitting

Бандл был одним куском: `Portfolio` (≈6000 строк со всеми крипто-шитами),
`Credits` и `Settings` ехали к каждому, кто открыл приложение и дальше
обзора не пошёл.

`Dashboard` оставлен в основном чанке — это стартовый экран. Остальные
четыре через `React.lazy` + `Suspense` с тем же `SplashScreen` в fallback.
Хорошо ложится на уже имеющуюся механику `visited`: страница и так
монтируется только при первом заходе на неё.

### 5. Самохостинг шрифта Onest

`<link>` на `fonts.googleapis.com` блокировал первый рендер (DNS + TLS + CSS
к чужому домену, и только потом сами файлы), а в нативной оболочке означал,
что без сети приложение остаётся без шрифта.

Взята **variable**-версия: два файла на все веса 400–800 вместо пяти
статических начертаний на подмножество.

| | было (Google) | стало |
|---|---|---|
| файлов | 5 весов × 7 подмножеств | 2 (cyrillic + latin) |
| байт (cyrillic+latin) | 242 КБ | 48.5 КБ |
| сторонних запросов | 3 (2 preconnect + CSS) | 0 |

Вес 900 из запроса убран: в `styles.css` он не используется (по факту нужны
400/500/600/700/800).

`unicode-range` перенесён из ответа Google в наш `@font-face` — браузер
по-прежнему качает кириллицу и латиницу независимо, по факту использования.
Лицензия OFL приложена рядом со шрифтом, как она того требует; инструкция
по обновлению — в `frontend/src/assets/fonts/README.md`.

## Что проверено, а что нет

Проверено:

- `npm run typecheck` — чисто; `./venv/bin/ruff check backend storage` — чисто.
- `npm run build` — собирается, чанки разделились как задумано.
- В браузере на 375×812: экран входа рендерится, WebP-логотип с прозрачностью
  корректен на тёмной теме, оба подмножества Onest в статусе `loaded`,
  `getComputedStyle` даёт `Onest`, запросов к google-доменам ноль, консоль
  чистая.
- `.refresh-bar` — через `getComputedStyle`: `position: fixed`, 3px,
  `z-index: 60`, анимация `refresh-bar-slide` на `::after`.

**Не проверено вживую:** поведение после входа в аккаунт — переключение
вкладок без ремонта, обновление после мутации без сплэша, pull-to-refresh с
полосой. На машине не поднят ни Docker, ни Postgres, поэтому дальше экрана
входа дойти не удалось. Логика подтверждена только типами и чтением кода;
при первом запуске с живой базой эти три сценария стоит прокликать.

**Не проверено:** синтаксис `infra/nginx.conf` (`nginx -t` не на чем
выполнить — ни Docker, ни локального nginx). Директивы стандартные, но
перед деплоем имеет смысл прогнать
`docker compose -f infra/docker-compose.yml build web`.

## Известные уязвимости / осознанные риски

Компромиссов по безопасности не вносилось. Наоборот, добавлены `nosniff` и
`Referrer-Policy`, которых не было.

Одно сознательное **не**-ужесточение: `X-Frame-Options` и
`frame-ancestors` не выставлены, потому что сломали бы Telegram Web. Это
значит, что приложение по-прежнему можно встроить в iframe с чужого сайта.
Если Telegram Web перестанет быть нужен, заголовок стоит добавить.

Шрифт и лицензия OFL добавлены в репозиторий (два `.woff2`, 49 КБ) —
осознанное увеличение веса репозитория в обмен на отсутствие зависимости
от чужого CDN.

## Открытые вопросы

- `docs/ISSUES.md` датирован 2026-07-06 и разошёлся с кодом: пункты 1, 2, 6,
  6a и 12 уже закрыты, а счётчики («121 функция») устарели. Нужен отдельный
  проход по нему, здесь он не трогался.
- Лint фронтенда даёт 163 предупреждения, из них ~86 —
  `useExhaustiveDependencies`. Проп `refreshToken` попадает в ту же
  категорию («specifies more dependencies than necessary»), потому что он
  триггер перезагрузки, а не читается в теле эффекта. Это ровно тот же
  паттерн, что уже был с `[user.bank_account_id]`. Точечно глушить не стал:
  разбирать эту кучу имеет смысл целиком, а не по одной строке.
- CSS не делится по чанкам: один файл 218 КБ на всё приложение. Под gzip это
  35 КБ, поэтому отдельной задачей не выносилось.
