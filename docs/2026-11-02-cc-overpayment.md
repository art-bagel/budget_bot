# Переплата по кредитной карте: учёт и отображение

Уровень: **L** (деньги) + UI/UX-трек. Ветка `claude/cc-overpayment`.
Статус: **выпущено в прод 02.11.2026.** План утверждён владельцем 02.11.2026 («Да, по рекомендациям»: вариант A, «Обзор» — да, карта → инвестсчёт — отдельной задачей).

## Контекст

Модель, согласованная с владельцем 02.11.2026 (см.
`docs/2026-11-02-cc-repay-after-reversal.md`):

- бюджет = cash-счета + балансы карт + бюджетный долг карт;
- бюджетный долг карты — сумма бюджетных проводок по неотменённым
  `account_transfer` с участием карты (снятие с карты на cash-счёт даёт `+`,
  погашение — `−`);
- погашение карты с cash-счёта списывает из `Unallocated`
  `LEAST(платёж, долг)`. Переплата (плюс на карте) остаётся свободными
  деньгами владельца: бюджет её не теряет.

Свободный остаток в UI = `Unallocated` + `FX Result`.

## Цель

1. **Учёт.** Перевод с кредитного счёта на cash-счёт добавляет в `Unallocated`
   получателя только ту часть, которая уводит карту ниже нуля. Возврат своего
   плюса с карты бюджет не меняет.
2. **Отображение.** Переплату видно в разделе «Кредиты»: в плитке карты и в её
   шторке. «Доступно» считается как лимит + баланс карты.

Не входит в задачу:

- погашение кредитов/ипотеки (`put__repay_credit_account`), переводы
  карта → инвестиционный счёт (вопрос владельцу 3, «Известные ограничения»);
- пересчёт прошлых операций. На проде (только чтение, 02.11.2026) нет ни одного
  перевода с кредитного счёта, сделанного при плюсе на нём, кроме сторно
  2025153. Двойных зачислений нет, правка данных не нужна;
- форма перевода (`AccountTransferDialog`): «Доступно» там уже лимит + баланс
  (`availableCreditLimit`), то есть с переплатой.

## Диагностика

Сейчас в `put__transfer_between_accounts` ветка `_to_account_kind = 'cash'`
всегда пишет `+_cost_base` в `Unallocated` получателя. Пример: карта 0,
погашение 159 при долге 0 → бюджет не меняется, карта +159. Перевод 159 с карты
на Main → `Unallocated` +159, бюджетный долг карты +159. Итог: бюджет больше
реальных денег на 159, пока следующее погашение не спишет этот «долг». Если
карту больше не гасят — навсегда.

## Решение

### 1. SQL: `put__transfer_between_accounts`

Баланс источника уже читается под `FOR UPDATE` (`_bank_balance`). Для перевода
с кредитного счёта на cash-счёт:

```
own   = GREATEST(0, LEAST(_amount, _bank_balance))   -- свой плюс, уже в бюджете
_budget_credit_base = round(_amount - own, 2)
```

Для остальных переводов на cash `_budget_credit_base = _cost_base`, как
сейчас. Если `_budget_credit_base = 0`, бюджетной проводки нет (как у
погашения при нулевом долге).

- Правило общее для любого `account_kind = 'credit'`, не только
  `credit_card`: свой плюс на любом кредитном счёте уже в бюджете. У кредитов
  и ипотеки плюса на практике не бывает, поведение для них не меняется.
- Бюджетный долг считается по тем же бюджетным проводкам, поэтому растёт
  только на часть ниже нуля. Формула погашения `LEAST(платёж, долг)` не
  меняется.
- Отмена (`put__reverse_operation`) зеркалит проводки операции. Отмена
  возврата переплаты без проводки бюджета ничего не возвращает в бюджет;
  отмена частичного перевода списывает ровно его бюджетную часть, а сама
  операция выпадает из долга (`NOT EXISTS reversal`).
- Валюта: перевод с кредитного счёта не в базовой валюте запрещается
  (`RAISE EXCEPTION`, как в `put__record_expense`). Форма такого и так не
  предлагает. На проде (только чтение, 02.11.2026) переводов с кредитных
  счетов не в рублях или не на cash-счёт нет ни одного.

`set__archive_credit_account`: архив только при нулевом балансе
(`_balance <> 0` вместо `< 0`), иначе переплата пропадёт вместе с картой, а
вернуть её переводом нельзя (перевод требует `is_active`). Текст ошибки: «На
карте переплата — сначала переведите её на счёт». В UI кнопка «Перенести в
архив» видна только при нулевом балансе.

Миграции нет: функции пересоздаёт `run_migrations.sh` при деплое.

### 2. Фронтенд: раздел «Кредиты»

Расчёт выносится в чистую функцию `creditCardView(balances, limit)` в
`frontend/src/utils/creditCard.ts` (сейчас `accountDebt` живёт внутри
`Credits.tsx`): `used = max(0, −баланс)`, `overpayment = max(0, баланс)`,
`available = max(0, лимит + баланс)`, `usedPct`. Баланс — сумма
`historical_cost_in_base`, как сейчас.

**Вариант A (рекомендую).** Лимит не смешивается со своими деньгами.

Плитка в списке (переплата 1 500 ₽, лимит 50 000 ₽):

```
┌──────────────────────────────────────────┐
│ Т-Банк  Тестовая кредитка      +1 500 ₽  │
│                               переплата  │
│ 24.9% годовых · платёж 15-го             │
│ Использовано 0 ₽ из 50 000 ₽         0%  │
│ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │
└──────────────────────────────────────────┘
```

Справа вместо «0 ₽ / использовано» — «+1 500 ₽ / переплата». Цвет суммы —
`--text`, без зелёного: `--pos` на белом ниже 4.5:1. Строка лимита без
изменений.

Шторка карты, блок «Лимит карты»:

```
Лимит карты                              0%
░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
Использовано 0 ₽ · доступно 51 500 ₽
Переплата 1 500 ₽ — ваши деньги на карте
```

- первая строка без «из 50 000 ₽», когда есть переплата (лимит — в «Условиях»,
  строка «Лимит»); без переплаты строка прежняя: «Использовано X · доступно
  Y из L»;
- «доступно» = лимит + баланс. Это заодно чинит текущее «лимит − долг», которое
  при переплате теряет её;
- вторая строка — только при переплате, тот же класс `credits-util__legend`.

**Вариант B (предложение владельца).** Плитка: «Использовано 0 ₽ из 51 500 ₽».
Шторка: «доступно 51 500 ₽ из 50 000 ₽». Минус: «из» больше лимита читается
как ошибка, а процент считается от чего-то, что не лимит.

Состояния: без лимита (`credit_limit` 0/null) блок лимита не показывается, как
сейчас; переплата в плитке видна и без лимита. Долг и переплата одновременно
невозможны (один баланс в базовой валюте). Длинные суммы — проверка на 375px:
«Переплата 1 234 567,89 ₽ — ваши деньги на карте» переносится, легенда уже
многострочная.

Переиспользуются: `formatAmount`, классы `tile__debt`/`tile__debt-label`,
`credits-util__legend`. Новых токенов и компонентов нет.

Форма перевода (`AccountTransferDialog`): у карты в роли «куда» при плюсе
подпись «Переплата» вместо «Задолженность».

### 3. «Обзор» (вопрос владельцу 2)

`Dashboard.tsx` складывает балансы всех кредитных счетов и обрезает итог
`Math.max(0, …)`. `total_bank_historical_in_base` считает только cash-счета.
Если переплата на карте — единственный «плюс», её на «Обзоре» нет нигде. Если
есть долг по другой карте, переплата уменьшает строку «Кредиты».

Предложение: строка «Кредиты» = сумма долгов по счетам (как в разделе
«Кредиты»), переплата всегда прибавляется к «Всего», переключатель «Кредиты»
влияет только на долги. Расчёт выносится в `creditTotals(balancesByAccount)`
в `utils/creditCard.ts` (→ `{ debt, overpayment }`) ради юнит-теста.

## Критерии приёмки

1. Перевод с карты с плюсом X на cash-счёт суммой ≤ X не меняет свободный
   остаток и не создаёт бюджетного долга: следующее погашение (переплата) не
   списывает свободный остаток. Так же для переплаты, возникшей после отмены
   расхода по карте.
2. Перевод с карты с плюсом X суммой S > X увеличивает свободный остаток на
   S − X; следующее погашение S − X списывает из свободного остатка S − X.
   Граница: S = X + 0,01 → в бюджет и в долг ровно 0,01.
3. Перевод с карты в ноль/минус (обычное снятие) работает как раньше: весь
   перевод в свободный остаток.
4. Отмена перевода из п. 1 не меняет свободный остаток и возвращает плюс на
   карту; отмена перевода из п. 2 списывает S − X и не оставляет бюджетного
   долга (следующее погашение ничего не списывает).
5. Перевод с кредитного счёта не в базовой валюте отклоняется.
6. Карту с ненулевым балансом (долг или переплата) нельзя заархивировать; кнопка
   архива видна только при нулевом балансе.
7. Плитка карты с переплатой показывает «+сумма ₽» и подпись «переплата»;
   без переплаты — как сейчас.
8. Шторка карты с переплатой показывает «доступно = лимит + переплата» и строку
   «Переплата … — ваши деньги на карте»; без переплаты легенда прежняя.
9. В форме перевода карта с плюсом в роли «куда» подписана «Переплата: …».
10. Если владелец согласует п. 3: «Всего» на «Обзоре» включает переплату при
    любом положении переключателя, строка «Кредиты» — только долги.
11. Нет новых нарушений axe на «Кредитах» (список и открытая шторка карты с
    переплатой) в обеих темах.

## Откат

Откатить коммиты и задеплоить. Миграций и правок данных нет. Переводы,
сделанные после деплоя, останутся с меньшей бюджетной проводкой — это и есть
правильный учёт, пересчитывать их не нужно.

## Известные ограничения

- **Переплата между владельцами.** Если карту переплатили со счёта семьи, а плюс
  вернули на личный счёт, бюджет семьи сохранит эти деньги, а личный не
  получит. Сумма бюджетов верна, но деньги «не того» владельца. Кто внёс
  переплату, система не хранит. Сейчас (до правки) в этом случае бюджет
  удваивается, так что правка не хуже.
- **Карта → инвестиционный счёт** (если владелец не включит в задачу, вопрос
  3). Свой плюс, ушедший с карты на инвестсчёт, не списывается из бюджета, и
  бюджет остаётся завышенным на него. Заёмная часть такого перевода не создаёт
  бюджетного долга, поэтому её погашение с cash не уменьшает свободный остаток.
  Это было и до задачи. На проде таких переводов нет.
- Порядок операций: как и в прошлой задаче, отмена не последней операции по
  карте не пересчитывает поздние переводы.

## Известные уязвимости / осознанные риски

Нет. Права доступа и проверки лимита не меняются.

Формула для базовой валюты проверена на инварианте «бюджет = cash + баланс карты
+ бюджетный долг»: любая бюджетная проводка `c` по переводу карта → cash
одновременно двигает долг на `c`, поэтому инвариант держится при любом `c`;
`c = amount − own` дополнительно держит долг ≈ `max(0, −баланс)`. Сценарии:
переплата из погашения, переплата из отмены расхода по карте, частичная трата
переплаты, перевод больше переплаты, отмена каждого вида, повторная отмена
погашения после возврата переплаты — расчёт сходится. Других путей «кредитный
счёт → cash с зачислением в бюджет» нет: доход только на cash
(`put__record_income`), обмен валют только cash, `put__transfer_bank_crypto` —
только cash/коллекции, `put__repay_credit_account` не принимает карту как
источник.

1. **ок** — базовая валюта, отмены, конкурентность. Баланс карты читается после
   `FOR UPDATE` строки источника (§1 гайдлайнов); если строки баланса ещё нет,
   блокировка пустая, но баланс 0 → `own = 0`, поведение как сейчас. Сторно
   имеет тип `reversal` и в долг не попадает, отменённый оригинал исключается
   `NOT EXISTS` — критерий 4 сходится. Упрощение: для базовой валюты то же самое
   без деления — `round(_amount - own, 2)`, `_cost_base = round(_amount, 2)`.

2. **исправить** — иностранная валюта. Пропорция `_cost_base * (amount − own) /
   amount` не соответствует тому, как считается `_cost_base` у кредитного
   источника (строки 142–174): стоимость набирается только из FX-лотов карты, то
   есть ровно из «своей» части, а заёмная часть получает нулевую стоимость; если
   лотов нет, `_cost_base := round(_amount, 2)` — сумма в валюте записывается как
   рубли. Пропорция смешает стоимость своей части с заёмной, и бюджетная
   проводка не совпадёт ни с одной из частей. Предлагаю не `ponytail:`, а явный
   запрет в SQL: перевод с кредитного счёта не в базовой валюте →
   `RAISE EXCEPTION` (как в `put__record_expense`, строка 103: «Credit accounts
   only support base-currency expenses»). До этого — проверить на проде (только
   чтение), что таких переводов нет; если есть — вопрос владельцу. Добавить
