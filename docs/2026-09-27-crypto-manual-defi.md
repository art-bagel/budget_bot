# Ручной DeFi: большой проход 27.09.2026

Продолжает ручные обмены и lending (`1d77185`, `13ad3b7`). Все изменения общие:
они работают для нового владельца без исторического импорта. Исторические
суммы и проводки не пересоздавались.

## Результат

| Действие в интерфейсе | Проведение и проверенное поведение |
|---|---|
| Создать стейкинг, залог или LP из своих активов | `create_protocol`: перенос стоимости и финансирования из исходных позиций |
| Создать залог сразу с займом | Создание и `borrow` в одном источнике; ссылка на созданную позицию, нулевая новая стоимость займа, компонентные единицы |
| Добавить залог / ликвидность | `top_up_protocol`, комиссия атомарна |
| Вернуть часть залога / стейкинга | `partial_close_protocol`: перенос доли основной стоимости и заёмных единиц |
| Начислить монеты внутри протокола | Новое действие `protocol_yield`: количество растёт без новых затрат; событие в истории DeFi |
| Получить награды стейкинга / комиссии LP | Нулевая стоимость, без расходования финансирования основной позиции |
| Полностью выйти из LP | `close_protocol`, политика `net_composition`; введённые рыночные оценки не подменяют перенос затрат |
| Полностью вернуть стейкинг / закрыть залог | Общий журнал, повтор запроса не повторяет возврат |
| Зачислить награду обычному криптоактиву | `position_income`: прежняя операция дохода с нулевой стоимостью внутри общего журнала; стабильный ключ |
| Списать сетевую комиссию | `fee`, ключ повтора; комиссии DeFi входят в источник основной операции и связаны с её историей |
| Объединить два залога в общий счёт протокола | Форма выбора другой позиции, подтверждение пользователя, общий идентификатор; запрещено объединять уже разные группы или задваивать активный долг одной монеты |
| Ликвидировать другой залог общего lending-счёта | Выбор залога в форме; долг остаётся на своей позиции, изъятие — на выбранной; стоимость тела переносится держателям долга |

Комиссия и действие — одна транзакция. Ошибка комиссии откатывает создание,
заём, движение и запись источника. Идентификатор запроса сохраняется при
неопределённом ответе и переоткрытии формы в той же вкладке.
API без request_id совместим, но повтор без ключа — новое действие.

Введённые количества передаются строками до 18 знаков. Чтение DeFi дополнено
точными строками основного и текущего количества, второго токена LP;
автоподстановка полного выхода использует их. Рыночные числа по-прежнему
остаются отображаемыми оценками, не источником себестоимости.

У ликвидации другого залога проверяются инвестиционный счёт, сеть и непустой
одинаковый `lending_account_key`. Совпадения названия протокола недостаточно.
История показывает настоящую залоговую монету и доступна в карточке залога.
Master и LP нельзя смешать. Добавлена форма «Общий счёт протокола»: можно
связать новые позиции вручную без импорта. Пользователь подтверждает, что они
обеспечивают общий долг; это не автоматическое доказательство из блокчейна.
Существующая отличающаяся идентичность не перезаписывается. Общий долг нельзя
дублировать на другом залоге той же группы.

Редактирование текущего состояния больше не может подменять количества,
полученные награды, долг или заёмные компоненты. Для начисления есть отдельная
форма. Редактирование APR/названия пула, комментария и оценок не является
исправлением исторической операции.

## Проверка

18 интеграционных тестов `scripts/crypto/test_manual_precision.py` через настоящие
API/storage/SQL на локальной preview, с полным откатом финансовых фикстур.
Добавлены пять больших сценариев к прежним 13:

1. Новый владелец: создание залога с займом 10,123456789012345678 → стейкинг
   заёмных монет → частичный возврат → начисление двух монет → получение
   награды → полный возврат. Финансирование сохраняется. Пополнение и возврат
   залога переносят стоимость. Проверены повтор и откат при недостаточной комиссии.
2. LP: 100 монет стоимостью 10 000 RUB + 1000 монет стоимостью 10 000 RUB;
   награды и выход 10 / 2000. Остаточная стоимость: 1000 / 19 000 RUB.
   Рыночные значения из старого клиента не меняют распределение.
3. Финансируемый LP: награды не забирают единицы основной позиции;
   выход 5 / 15 вместо 10 / 10 переносит по 5 единиц займа к двум монетам.
   Подмена metadata и недопустимая точность отклоняются.
4. Создание общего lending-счёта через ручной API без импорта, повтор
   подтверждения группы и ликвидация другого залога: изъятие 2 монет стоимостью 200 RUB
   из 20 монет / 2000 RUB, погашение одной монеты долга. Залог уменьшается
   до 18 / 1800 RUB, долг до 9; основной залог на долговой позиции не списан.
   Другая идентичность счёта отклоняется; проверена история выбранного залога.
5. Награда и отдельная комиссия: точные количества и повтор после следующего
   действия без двойного зачисления/списания.

Прежние проверки обменов, неизвестной стоимости, частичного погашения,
процентов, ликвидации, прав доступа и банковского расхода также проходят.
Typecheck и Ruff пройдены; frontend lint: 159 предупреждений, 18 информационных
замечаний, ошибок нет. Артефакты: `outputs/crypto-manual-defi/` (локально, не git).

## Применение и незакрытые границы

Применение восьми SQL-функций к двум локальным dev-базам сохраняет прежние
определения и сверяет отпечатки 17 финансовых таблиц. API/web собираются из
криптоветки, production не затрагивается. Для отката определения изменившей
сигнатуру `put__lending_liquidate` сначала удалить новую функцию, затем загрузить
сохранённое определение: простое добавление старой перегрузки недостаточно.

Это не объявление всего ручного учёта и R2 завершёнными:

- Частичный выход LP требует доли выведенных LP-токенов и отдельного расчёта
  выводимой части. Сейчас явно недоступен, в том числе без финансирования;
  получение комиссий и полный выход доступны. Согласно чеклисту это будущий
  сценарий, не потерянная операция текущей истории.
- Неизвестный штраф ликвидации не поддерживается ручной формой как отдельное
  неизвестное значение: форма требует подтверждённое число, включая ноль.
  Старые исторические неизвестные остаются неизвестными.
- Объединённый старый API `accrue` не является новой ручной формой. Для обычного
  ввода доступны отдельные события дохода на залог и процентов по долгу.
- Исправление прошлого с версиями и зависимым пересчётом — R2.2, не выполнено.
  Ввод даты раньше последующих событий отклоняется, старые протокольные остатки
  нельзя исправлять обходным редактированием текущего количества.
- Полная авторизованная визуальная приёмка и банковские крайние случаи остаются
  в R2.1/R2.3 и R3. На открытом dev-браузере отображается форма входа; тесты
  через API не выдаются за пользовательскую приёмку всех экранов.
