## 1. Обмен USDT (TON) → USDC (Arbitrum) в банке

**Что было.** Кнопка обмена неактивна: окно обмена прямо запрещало пару
«крипта → крипта», а API отвечал `Crypto-to-crypto exchange is not supported in
banking MVP`.

**Что сделано.**

- `put__swap_bank_crypto_asset`: FIFO-лоты отдаваемой монеты (кроме «ждёт
  категории расхода») списываются, их себестоимость целиком переходит в один
  новый лот полученной монеты. Операция `exchange`, без проводок бюджета: ни
  продажи, ни дохода, ни FX-result — как `basis_policy=carry` в портфеле.
- Новый вид банковского журнала `bank_swap`: зарегистрирован в
  `put__journal_bank_operation`, `put__crypto_source_event` (два списка),
  `put__execute_bank_journal_command`, `put__crypto_funding_components`.
  Журнал даёт идемпотентность по `request_id` окна обмена и исправление истории.
- `POST /operations/exchange` с двумя крипто-активами вызывает журнал;
  `ExchangeSheet` больше не блокирует пару.
- SQL-тест `tests/bank_crypto_swap.sql`: перенос себестоимости 14 000, пропуск
  «ждущих» единиц с понятной ошибкой, повтор без новой операции, отмена,
  лоты = проекция.

**Проверка на копии production** (дамп 29.09 ~13:40 UTC, откат транзакции):
180,2 USDT → 180 USDC на «Main»: себестоимость 15 273,71 ₽ перенесена, USDT
осталось 119,73 на 10 487,82 ₽, проводок бюджета нет.

## 2. Курсы ETH и USDC

**Что было.** CoinGecko отвечает серверу 403 (CloudFront), запасного источника
для монет вне TON не было.

**Проверены с сервера:** CryptoCompare — нужен ключ (401); CoinPaprika — 200,
рубли есть, но лимит 20 000 запросов в месяц на общем внешнем адресе исчерпан
(`ratelimit-remaining: 0`); рублёвые пары Binance устарели (ETHRUB 181 тыс. ₽
при рынке ~229 тыс., USDTRUB 91,10 при 84,37); Bybit, OKX, Kraken — 200.

**Что сделано.** `backend/app/exchange_prices.py`: цена пары в USDT со спота
Bybit (ваши ETH и USDC на Bybit) × курс USDT (TON) из TonAPI в RUB/USD/EUR.
Монеты сети TON сюда не попадают — их цена только по мастер-адресу. Кэш 2 мин,
устаревшее значение до 30 мин, как у остальных источников. Порядок в
`/crypto/prices`: CoinGecko → TonAPI (TON) и Bybit (остальные).

Живая проверка: ETH 229 967 ₽ / 2 727,90 $, USDC 84,31 ₽ / 1,00 $.

## 3. Монеты Telegram Wallet — в сети TON

**Что было.** DOGS, MAJOR, HMSTR записаны с сетью `telegram` и адресом
`service:telegram:<символ>`; для курса пришлось держать отдельную таблицу
соответствий.

**Что сделано.** Миграция `050_telegram_wallet_coins_on_ton.sql`: сеть `ton`,
адрес — мастер жетона, сверенный с TonAPI `/v2/jettons` (все три `whitelist`,
9 знаков — как в базе). ID, лоты, позиции и ссылки журнала не меняются.
Таблица `TELEGRAM_WALLET_JETTONS` удалена: курс идёт по мастер-адресу.

На копии production миграция применилась; записей с такими адресами в сети TON
до неё не было, конфликта уникальности нет.

## Откат

Revert коммитов. Миграцию 050 откатывает обратный `UPDATE` (мастер-адрес →
`service:telegram:<символ>`, сеть `telegram`) для ID 26–28; операции обмена
отменяются штатно.

## Известные уязвимости / осознанные риски

- Курс ETH/USDC составной (Bybit × TonAPI): при сбое любого из двух курса нет.
  Только для отображения, в учёт не попадает.
- Скрипты исторического импорта (`scripts/crypto/build_fourth_hundred_plan.py`
  и др.) по-прежнему описывают эти монеты как `service:telegram:*`. Для
  production они больше не запускаются; при повторной сборке истории с нуля
  миграция 050 приведёт идентичности к TON.
