## БД и доменный слой

### Контракт ошибок SQL → API → UI
Сейчас plpgsql делает `RAISE EXCEPTION 'Insufficient investment balance...'`, а фронт
переводит на русский через `text.includes(...)` в `frontend/src/api.ts`
(`normalizeApiErrorMessage`). Любая правка текста в SQL молча ломает русское сообщение.

Целевая схема: `RAISE EXCEPTION ... USING ERRCODE` / структурированный код
(`ERR_INSUFFICIENT_BALANCE`), бэкенд отдаёт `{code, params}`, фронт держит словарь переводов.
Разовая работа, развязывающая три слоя, сцепленных текстом.

### Сверка целостности read-проекций
Модель событийная: `operations` + entries — источник истины, `current_bank_balances` /
`current_budget_balances` / `current_crypto_balances` — проекции; `rebuild_current_balances`
уже существует. Нужен ночной джоб (или эндпоинт «проверить целостность» в настройках),
который сравнивает `SUM(bank_entries.amount)` с проекциями и сигналит при дрейфе.
С учётом частоты ручных правок SQL это ранняя сигнализация вместо
«баланс уехал, не знаю когда».

### Контрактные тесты SQL ↔ Python
`get__*`-функции возвращают `jsonb`, Pydantic-модели дублируют структуру руками.
Минимальный вариант: тест вызывает каждую `get__*`-функцию на тестовой БД и валидирует
ответ соответствующей Pydantic-моделью. Дешевле composite types, рассинхрон ловит.

### Индексная ревизия
Прогнать `get__operations_history` / `get__operations_analytics` через `EXPLAIN ANALYZE`
на реалистичном объёме, добавить составные индексы по `(owner, operated_at)` где нет.
Партиционирование пока не нужно.

## Бэкенд

### Идемпотентность операций
Двойной тап или ретрай после таймаута создаёт дубль расхода/перевода — защиты нет.
Клиент генерирует `client_op_id` (uuid) на каждую форму, `operations` получает уникальный
индекс по нему, повторный запрос возвращает уже созданную операцию.

### Генерация TypeScript-клиента из OpenAPI
FastAPI уже отдаёт схему; `openapi-typescript` + лёгкая обёртка заменят вручную
поддерживаемые `types.ts` и сигнатуры `api.ts`. Рассинхрон типов исчезает как класс проблем.

### Наблюдаемость
`logging` без структуры и request id. Минимум: request-id middleware, JSON-логи, Sentry
на бэкенд и фронт. Особенно полезно для `tinkoff_sync.py`, где ошибки глотаются широкими
`except Exception`.

### Фоновые задачи как отдельный контур
Scheduler живёт внутри API-процесса, Tinkoff-синк выполняется в запросе. При появлении
второго тяжёлого синка (он-чейн история) вынести в отдельный воркер (arq на Redis)
со статусами задач; фронту отдавать прогресс.

### Бэкапы
Данные финансовые, живут в docker-томе на одном сервере. Cron с `pg_dump` в
S3-совместимое хранилище + периодическая проверка восстановления.

## Фронтенд (архитектура)

### TanStack Query
Данные тянутся сырым `fetch` в каждом компоненте; обновление — через `refreshKeys`,
который ремаунтит страницу целиком (`<ErrorBoundary key={refreshKeys[id]}>`): теряется
скролл, всё перезапрашивается, optimistic-обновлений нет. Query даёт кэш, инвалидацию по
ключам («создал расход → инвалидируй dashboard и operations»), фоновое обновление и ретраи.
Самое рычажное изменение фронта; заодно упростит распил `Portfolio.tsx`.

### Ленивая загрузка страниц
Всё приложение — один бандл; 6000-строчный Portfolio грузится до первого рендера дашборда.
`React.lazy` по страницам + прелоад при переключении таба.

### URL-состояние / deep links
Страницы переключаются локальным `useState` — нельзя дать ссылку из бота вида
`startapp=portfolio`. Лёгкий роутер (wouter) + обработка `start_param` откроет сценарий
«бот прислал отчёт → тап → сразу нужный экран».

### Мгновенный старт с кэшем
Mini App каждый раз открывается со сплэша и ждёт сеть. Сохранять последний ответ дашборда
в `localStorage` / Telegram CloudStorage и показывать сразу (с пометкой «обновляется…»).

### Виртуализация истории операций
При годе активного использования список в Operations начнёт тормозить;
`@tanstack/react-virtual` решает заранее.

## UX / UI

### Скорость ввода расхода — главная метрика бюджетника
FAB «+» прямо на дашборде, предзаполненные последний счёт и последняя категория, крупная
суммовая клавиатура, кнопка «повторить» у частых операций. Если записать расход дольше
5 секунд — учёт бросают.

### Telegram-native возможности
- haptic feedback на подтверждения;
- `MainButton` вместо кнопки внутри формы (всегда над клавиатурой);
- пуш-уведомления через бота: «scheduled expense не выполнился» сейчас виден только в UI,
  приглашение в семью логично получать сообщением.

### Инсайты, а не только учёт
- «можно тратить N ₽/день до конца месяца» на дашборде;
- месячный итог сообщением от бота;
- тренд категории за 6 месяцев в деталке категории.

### Экспорт / импорт
Реальный рабочий процесс включает Excel (xlsx-файлы в корне репо). Встроенный экспорт
операций в CSV/XLSX и импорт банковских выписок (не только через Tinkoff API).

### Портирование редизайна
Направление зафиксировано в `ui-redesign-concepts/` (warm paper + ember, Golos Text,
шесть концептов). Сначала завести дизайн-токены (CSS custom properties: цвета, радиусы,
типографика, spacing) одним PR, затем переносить концепты поэкранно — каждый экран
становится механической заменой классов, светлая/тёмная темы остаются консистентными.
