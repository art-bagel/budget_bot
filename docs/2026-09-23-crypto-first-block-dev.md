## Как продолжить

Рабочая директория `.worktrees/crypto-accounting`, ветка
`codex/crypto-accounting-recovery`. Все личные артефакты игнорируются в `outputs/`:

- `crypto-first-block-dev/plan-v2.json` — 100 принятых описаний, команды готового
  непрерывного префикса и хеши источников;
- `crypto-first-block-dev/state-v3.json` — окончательный dev-владелец 1000002,
  счета, сохранённые запросы/ответы и контрольные результаты;
- `state-v1.json`, `state-v2.json` — предварительные запуски, не продолжать;
- `state-recovery-check.json` — проверка восстановления того же владельца;
- `preview_app.py`, `vite-preview.mjs` — локальный предпросмотр без scheduler.

База `boundary_usd_clean`, socket `/private/tmp/crypto-portfolio-audit.vl7Ix1`,
порт 55441. Она сохраняется, не удалять при продолжении. Локальное приложение
доступно на `http://127.0.0.1:5187`, API на 8017, только loopback.
Предпросмотр использует стандартные router/auth приложения; для тестового
владельца настроен существующий dev-вход Telegram. Scheduler отключён.
Отдельный Vite config обходит несовместимость общего plugin-react/Vite;
общие зависимости проекта не изменены.

```sh
python scripts/crypto/build_first_block_replay.py --output outputs/crypto-first-block-dev/plan-v2.json
python scripts/crypto/replay_first_block_dev.py --socket /private/tmp/crypto-portfolio-audit.vl7Ix1 --plan outputs/crypto-first-block-dev/plan-v2.json --state outputs/crypto-first-block-dev/state-v3.json
```

Использовать Python проекта с asyncpg/FastAPI. Загрузчик ограничен локальными
`boundary_` базами, блокирует параллельный запуск с тем же state, не разрешает
менять уже проведённые входы. Новые команды следует добавлять после №6;
изменение старой операции требует новой версии/пересборки, не ручной правки
остатков. Отдельного безопасного механизма исторических исправлений пока нет.

Следующий конечный результат по-прежнему **вся первая сотня, сверенная в боте**.
Промежуточный участок 1–6 не заменяет этот критерий и не означает закрытие сотни.
