## Как воспроизведено

В отдельной базе `crypto_release_20260928_134135` применены миграции 036–049 и
текущие функции криптоветки. Использована прежняя проверенная подготовка:
архив заменяемого криптографа, отмена неучтённого расхода №19911 и запись остатка
5 318 633,57 RUB; освобождено 2 247 804,43 RUB без нового дохода.

Копируются определения счетов/монет и идентификаторы вставок для сохранения
связей. Готовые количества и себестоимости из dev **не подставляются**:
они вычисляются командами журнала. Штатный механизм воспроизведения использует
старые даты создания для сохранения порядка FIFO. Изменённые идентификаторы
проводок перечислены в приватном `identity-map.json`.

Первая попытка остановилась на конфликте номера записи с существующей
серверной покупкой; транзакция replay полностью откатилась. Во второй попытке
номера исходной серверной покупки зарезервированы, конфликтующие импортируемые
записи перенумерованы. Все проверки пройдены до фиксации. Результат дополнительно
проверен отдельным `--verify-only` в откатываемой транзакции.

Скрипт `scripts/crypto/rehearse_release.py` намеренно ограничен одной локальной
базой. Это инструмент переноса конкретного принятого журнала, не пользовательская
бизнес-логика и не команда для запуска на production. Подготовка сохраняется
отдельной транзакцией; при неуспехе replay локальная база остаётся подготовленной,
не объявляется готовой. Повтор завершённого переноса запрещён; для проверки
завершённого результата используется `--verify-only`.

## Объединение банковских USDT после репетиции

28.09.2026 по согласованию объединены две идентичности TON USDT: старая без
контракта и актуальная с контрактом. Выполнена обычная журналируемая операция
`bank_asset_merge` в dev, `crypto_review_20260928` (:8081) и базе репетиции.
Она переносит оставшиеся лоты, сохраняя их ID, количества, стоимость и даты FIFO.
Прошлые покупки и исходные команды не переписаны; новый доход, расход и рублёвый
обмен не создаются. Исторические ссылки на старую запись остаются доступны.

Остаток единственной записи: **270,88168405 USDT**, себестоимость **22 355,42 RUB**.
Рубли, категории и портфель не изменены. После ручного расхода 110 USDT за
экскурсию останется **160,88168405 USDT**, если не добавлять другие операции.
Справочник скрывает проверенный устаревший дубль из нового выбора; публичное
создание актива не позволяет назначать такие административные ссылки.

Добавлены универсальная команда, API и кнопка объединения в карточке банка
для пары без контракта / с контрактом с одинаковыми монетой, сетью и точностью.
Проверены сохранность финансовых данных, повтор запроса, запрет чужого счёта

исправление исторической покупки. В копии production его ожидаемо блокируют

### Точность ручного распределения бюджета

После пользовательской проверки исправлен API `/operations/allocate`: денежная
сумма читается как Decimal и передаётся в PostgreSQL без двоичного float-хвоста.
Защита журнала с точностью до 18 знаков сохранена. Storage также переводит
числа от старых вызывающих клиентов через Decimal(str(value)). Проверка через
настоящий API и SQL: 2745,72; 0,88; 1,17; 0,01 и float 0,29, нечисловые и
неположительные суммы отклоняются; все тестовые проводки откатились.

В пользовательской копии свободный бюджет составляет −47 517,31 RUB. Ранее
предложенный возврат из него 2745,72 RUB арифметически закрывал распределение,
но недоступен по правилу достаточного остатка. Предложение отозвано; никаких
искусственных пополнений или обхода проверки не выполнено. Остаток категории
неучтённых расходов 1535,11 RUB не списан повторно.


### Исправление совокупного свободного остатка

Предыдущее заключение о недоступности перевода было ошибочным: −47 517,31 RUB
относится только к Unallocated. Вместе с FX Result +54 590,51 RUB свободно
7073,20 RUB. SQL-проверки одиночного и группового распределения теперь используют
ту же сумму, что экран. FX Result остаётся неизменным аналитическим показателем,
списание идёт из Unallocated. Проверены перевод 2745,72, группа, превышение
остатка, отрицательный FX, независимость обычной категории от FX, сохранность
банка и полный откат теста. Финансовые записи пользователя не изменены.
Функции установлены в review, dev и базе репетиции; production не менялся.
Сохранённые ранее дампы предшествуют этому исправлению: после их восстановления
нужно загрузить актуальные функции put__allocate_budget и
put__allocate_group_budget из ветки.


### Исправление источника стоимости связанных карточных расходов

28.09.2026 исправлена ошибка: `put__settle_crypto_fiat_sale` создавал расход
через общий FIFO банковских USD, хотя расход уже был связан с конкретной
продажей криптовалюты. Из-за этого «Подарок Сергею» потребил старые долларовые
лоты, оставленные для ручного распределения, вместо собственного лота №46.
Это ошибка привязки, а не обычное усреднение себестоимости USDT.

Теперь явная связь с продажей имеет приоритет. Универсальная функция
`put__reconcile_linked_fx_expenses` перераспределяет затронутые FX-списания,
уточняет бюджетные суммы и стоимость оставшейся валюты внутри журнала.
Количества денег и криптовалюты, категории, даты и идентификаторы существующих
расходов сохраняются. Неподдерживаемые сложные проводки отклоняются.

Для подарка 03.05.2026:

- исходная запись production: 142 USDT и 10 905,81 RUB;
- выписка Bybit: 143,9857 USDT за карточный платёж 141,98 USD;
- ошибочная стоимость строки расхода после импорта: 12 281,20 RUB;
- исправленная стоимость этой USD-строки: 10 620,30 RUB;
- ранее учтённая отдельно курсовая разница: −437,84 RUB;
- совокупная историческая стоимость израсходованной криптовалюты: 11 058,14 RUB.

Последняя сумма не приравнивается к старым 10 905,81 RUB: количество USDT
в ручной записи отличается от выписки. 10 620,30 RUB — стоимость USD-лота,
а не полная рублёвая стоимость покупки потраченных USDT.

Исправление применено в review :8081, dev :8080 и базе репетиции. В review
переоценены 12 связанных платежей и 11 последующих ручных USD-расходов.
Пользовательские распределения бюджета сохранены. Остаток USD — 0,41,
неучтённые расходы — 0 RUB, свободный бюджет — 4327,48 RUB. Остаток категории
«Подарки» теперь 3472,31 RUB. Бюджет целиком не объявляется совпавшим с production:
есть различия в исходных суммах платежей и более поздних операциях production.

Проверены повтор запроса и обычного вызова, запрет чужого пользователя,
сохранение общей исторической стоимости и всех количеств, отсутствие
отрицательных FX-лотов, соответствие банковского остатка сумме лотов.
Регрессионный тест нового ручного платежа с последующим исправлением
исторической покупки прошёл с откатом. Последнее обновление SQL не изменило
финансовые данные. Production не изменялся.
