# Коллекции: валюта по умолчанию в покупке и продаже

Ветка `claude/collectible-default-coin` (от `origin/main` df1f21a). Уровень **M**
(удобство формы, денежная логика не меняется).

## Цель

Почти все предметы покупаются и продаются за GRAM, но в формах валюта по
умолчанию — базовая (RUB), и её каждый раз приходится переключать. Нужно:

- при покупке предмета коллекции подставлять GRAM, если счёт его держит;
- при продаже, частичной продаже, доплате и комиссии подставлять ту валюту,
  за которую предмет был куплен;
- выбор по-прежнему можно поменять руками.

Как устроено сейчас (проверено 02.11.2026):

- `PortfolioPositionDialog`: `currencyCode` стартует с базовой валюты; эффект
  при смене счёта оставляет базовую, если текущая не в списке. Монеты счёта —
  `heldCoins` (балансы с `asset_type = 'crypto'` и остатком > 0), значение
  `crypto:<id>`.
- `Portfolio.tsx`: `createInitialCloseDraft`, `createInitialPartialCloseDraft`,
  `createInitialTopUpDraft`, `createInitialFeeDraft` берут
  `position.currency_code`. Список монет в селекте продажи — `cryptoAssets`
  (справочник), значение `crypto:<id>`.
- Валюта покупки хранится в `metadata.paid_crypto.{crypto_asset_id, symbol,
  quantity}`; у 419 из 436 предметов на проде она есть. Покупка за фиат —
  `paid_crypto` нет, валюта в `currency_code`.

**Не входит:** запоминание выбора пользователя между сессиями; другие типы
позиций; изменение самих операций.

## Критерии приёмки

1. Форма «Новая позиция», тип «Коллекция»: после выбора счёта, который держит
   GRAM с остатком > 0, валюта по умолчанию — `crypto:<id GRAM>`. Если GRAM нет,
   но есть ровно одна монета с остатком — она. Иначе базовая валюта, как
   сейчас. Смена счёта пересчитывает умолчание, если пользователь ещё не
   менял валюту руками в этой форме.
2. Переключатели «бесплатно» и «цена неизвестна» сбрасывают валюту как сейчас;
   возврат к покупке снова подставляет умолчание из п. 1.
3. Для предмета коллекции формы «Продать», «Продать часть / Вернуть часть»,
   «Вложить» и «Комиссия» стартуют с валюты покупки: `crypto:<paid_crypto.
   crypto_asset_id>`, если этот актив есть в списке селекта; иначе
   `position.currency_code`. Предмет, полученный бесплатно или с неизвестной
   ценой (без `paid_crypto`), стартует с GRAM, если GRAM есть в списке, иначе с
   `position.currency_code`.
4. Пользователь может выбрать любую другую валюту из списка; выбранное
   значение не перетирается до закрытия формы.
5. Остальные типы позиций (вклады, бумаги, крипта) стартуют как раньше.

Сид: добавляется монета `GRAM` в справочник (сеть `manual`, без цены и без
остатка). Остаток монет на счёте коллекции в сид не добавляется: монеты туда
попадают только с денежного счёта, а от его остатка зависят три браузерных
теста (снимок обзора, текст «не отменить», шторка обмена). Поэтому умолчание
покупки (критерий 1) проверяется юнит-тестом, а в браузере — умолчание
продажи.

Отдельные проверки из задания:

- Цикла в `useEffect` нет: зависимость — примитив `purchaseDefault`, эффект не
  читает `currencyCode`; старый эффект (`:238-246`) пропускает значения

- Смена счёта после ручного выбора: умолчание не пересчитывается (так и

  `position.currency_code` — есть в `currencies`. Для продажи `'all'` совпадает

  с `coinBalancesByAccountId` (`:4872`, `:4981`).

- Коммиты: английский императив, по одному шагу; секретов и реальных данных
