# Единый исходный журнал и связи без двойного учёта

## Результат прохода

Сборщик `scripts/crypto/build_unified_journal.py` объединяет восстановленные
источники в версионированный набор. Выход находится в игнорируемом каталоге
`outputs/crypto-unified-journal-2026-09-23-v3/`; предыдущие версии сохранены.
В БД в этом проходе ничего не записывалось.

| Движения main, включая явные исключения | 2653 |
| Строки Telegram из исходной таблицы | 132 |
| Строки Bybit | 1017 |

| Карточные конвертации из 79 строк | 23 |
| Группы обменов Bybit из 194 строк | 78 |

Получилось 1933 записи исходного журнала и 4871 уникальная ссылка на источник.
Это объединение уже известных данных, не 1933 новых неразобранных операции.
Внутренние пары не меняют общий портфель и не выводятся в пользовательскую
ленту. Источники обменов и Earn остаются для расчёта, без подробной биржевой ленты.

Каждая исходная строка имеет ровно одного получателя в `source-claims.json`.
Повторная претензия на строку, неверная сумма связанного перевода, повреждённая
арифметика или смешение версий останавливают сборку.

## Проверенные связи

31 связь объединена с main:

- 12 выводов USDT из Telegram: количество по блокчейну проверено; разница с
  округлённой таблицей сохранена, но не названа комиссией автоматически.
- Четыре пополнения Telegram с main: принятые ссылки перепроверены по действию,
  получателю и количеству TON. Старые номера событий не используются как ID.
- 12 серверных покупок: цепочечное поступление соответствует количеству покупки.
- Три продажи другу: исходящий перевод соответствует количеству продажи.

Ещё три серверные покупки имеют принятые ссылки на cold, не main:
27.05.2026, 25.06.2026, 27.07.2026. Они сохранены с явным требованием подключить
события cold. Для двух покупок 28.08.2025 и 07.09.2025 готовой цепочечной связи
в текущем денежном плане нет. Всего серверных покупок 17; ни одна не потеряна.

Связанная покупка/продажа заменяет основной перевод при будущей сборке команд,
а не добавляется вторым доходом/расходом. Комиссии и остальные движения события
сохраняются отдельно в его исходных строках.

## Порядок и контрольные остатки

У 11 возобновлений событий движения перемежаются с соседними событиями.
Например, строка 140 — комиссия события 61, а строка 141 продолжает событие 60.
Поэтому последовательность событий и последовательность отдельных движений
не тождественны. `movement-order.json` сохраняет все 2653 строки и их lt;
`interleaved-events.json` перечисляет найденные возобновления.

Исходная арифметика и непрерывность проверяются в порядке строк. Независимая
сумма изменений при группировке событий совпадает с исходными остатками на
100, 200, …, 1000 и 1049: 11 контрольных точек. Это количественная проверка,
не подтверждение себестоимости. Для будущего прогона внутри этих промежутков
нельзя слепо сравнивать промежуточные остатки по сгруппированным событиям;
нужно учитывать lt и связанные движения.

Порядок записей журнала пока предназначен для просмотра. Неизвестное время
не заменяется полуночью, часовые пояса внешних источников не угадываются.
Поле `display_order_is_not_posting_order` явно это фиксирует.

## Что остаётся

Это исходный журнал, **не готовый набор API-команд**. 1851 запись имеет хотя бы
один технический блокер; это не 1851 вопрос владельцу и не новый объём истории.
Многие блокеры устраняются одним общим преобразованием типа операций.

Нужно связать реальные счета и идентичности активов, определить общий порядок,
сопоставить экономические действия main с командами и обработать оставшиеся
переводы. 40 Telegram-строк пока не имеют окончательной команды. В частности,
слово «Доход» в выгрузке не доказывает награду: там может быть возврат основной
суммы из Earn. Четыре обмена с ответами владельца выделены отдельно; их объёмы
известны, историческая RUB-оценка пока неизвестна. Принятые решения вынесены
в `accepted-decisions.json`, их старые стоимостные трактовки не являются
правилами нового расчёта. В поля нового расчёта старые basis/profit не копируются.

Следующий проход: применить решения и связи к командам, включая внешние
кошельки и Ethereum в согласованных границах; затем полный прогон через API.
Исправление истории, PostgreSQL 17 и итоговый интерфейс остаются открыты.

`infra/db/Scripts/budgeting/tests/crypto_accounting/unified-source-results.json`.
