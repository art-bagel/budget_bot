# Подарки Telegram: автоназвание и подстановка атрибутов из t.me

Ветка `claude/gift-autofill` (от `origin/main` 349e720). Уровень **M**.

## Цель

1. Для вида «Подарок Telegram» название не вводится руками. Оно складывается из
   коллекции и номера в формате Telegram: `Vice Cream #12323`. Без номера
   (неулучшенный подарок) название — имя коллекции.
2. Когда в форме введены коллекция и номер, приложение само запрашивает
   атрибуты подарка и подставляет модель, фон, узор вместе с процентом
   редкости (`Pumpkin 3%` — формат, который `splitRarity` уже разбирает),
   ссылку на предмет и флаг «Улучшенный».

Источник: публичная страница `https://t.me/nft/<Slug>-<номер>` (без ключей и
авторизации). Проверено 01.11.2026: `og:title` = `Plush Pepe #1`, таблица
`tgme_gift_table` содержит строки `Model`, `Backdrop`, `Symbol` с `<mark>3%</mark>`.
Slug — имя коллекции без пробелов и дефисов, регистр не важен
(`plushpepe-1` отдаёт ту же страницу). Несуществующий номер отдаёт 200 с общей
страницей Telegram без таблицы.

**Не входит:** другие виды предметов; рыночная цена; массовое обновление уже
заведённых подарков; автозапрос в редакторе карточки (там только
пересчёт названия, см. открытые вопросы).

## Критерии приёмки

1. В форме «Новая позиция» при виде «Подарок Telegram» поля «Название» нет.
   Позиция создаётся с названием `<Коллекция> #<Номер>`, а без номера —
   `<Коллекция>`. Без коллекции кнопка создания неактивна.
2. После ввода коллекции и номера (пауза 500 мс) форма вызывает
   `GET /api/v1/portfolio/telegram-gift?collection=…&number=…`. Успешный
   ответ заполняет модель, фон, узор (с процентом), ссылку
   `https://t.me/nft/<Slug>-<N>`, ставит «Улучшенный» и берёт коллекцию из
   `og:title` (каноническое написание: `plush pepe` → `Plush Pepe`).
   Поля остаются редактируемыми.
3. Если подарок не найден или t.me недоступен — поля не трогаются, под
   номером подсказка «В Telegram не найден», создание не блокируется.
4. Бэкенд: endpoint только для авторизованного пользователя. Коллекция
   после удаления пробелов и дефисов — только `[A-Za-z0-9]{1,64}`, номер —
   только цифры до 9 знаков, иначе 400. Запрос уходит только на
   `https://t.me/nft/…` без следования редиректам, таймаут 8 с. Ответ
   `{title, collection, number, model, backdrop, symbol, link}`; нет
   таблицы или ошибка сети — 404 «Подарок не найден».
5. Редактор карточки подарка Telegram: поле «Название» скрыто, при
   сохранении название пересчитывается из коллекции и номера. Если
   коллекция пуста (старые записи вроде «Тестовый подарок»), прежнее
   название сохраняется.
6. Остальные виды предметов работают как раньше: название вводится руками.

## Безопасность

- URL строится из проверенного slug и номера, хост фиксирован, редиректы
  выключены — SSRF через параметры невозможен.
- Значения с t.me режутся до 200 символов и проходят ту же проверку
  `calc__collectible_metadata`, что и ручной ввод; в DOM попадают как текст.
- Запрос идёт с сервера: клиентский IP на t.me не уходит, а сам сервер и так
  ходит на tonapi/aitunnel.

## Что сделано

Коммиты ветки: план → бэкенд (`85c61bb`) → фронтенд (`3b976f1`) → документация.

**Бэкенд** — `backend/app/routers/portfolio.py`:
- `parse_telegram_gift(page)` разбирает `og:title` и строки `Model`,
  `Backdrop`, `Symbol` таблицы `tgme_gift_table`; `<mark>3%</mark>` становится
  текстом `Pumpkin 3%`, значения обрезаются до 200 символов. Страница без
  таблицы → `None`.
- `GET /api/v1/portfolio/telegram-gift?collection=…&number=…` (авторизация
  как у остальных ручек): slug `[A-Za-z0-9]{1,64}` после удаления пробелов и
  дефисов, номер `\d{1,9}`, иначе 400; запрос только на `https://t.me/nft/…`,
  `follow_redirects=False`, таймаут 8 с; нет таблицы или ошибка сети → 404.
- Ссылка собирается из названия со страницы (`Vice Cream` → `ViceCream-12323`),
  а не из `tg://nft?slug=`: t.me возвращает slug в том регистре, в каком его
  запросили. Это выяснилось на живом запросе `vice cream` → `vicecream-12323`.
- Тест `backend/tests/test_telegram_gift.py` добавлен в список юнит-тестов
  `scripts/check.sh` и CI одним коммитом.

**Фронтенд**:
- `utils/telegramGift.ts` — `telegramGiftSlug`, `telegramGiftTitle`. Модуль
  без импортов, чтобы `node --test` его запускал (тестируемые модули в этом
  репозитории держат без зависимостей: node не резолвит импорты без
  расширения и JSON). Тест `frontend/tests/telegramGift.test.ts`.
- `PortfolioPositionDialog.tsx`: для подарка Telegram поля «Название» нет,
  название считается при отправке. Через 500 мс после ввода коллекции и
  номера — запрос; ответ перезаписывает коллекцию (каноническое имя), номер,
  модель, фон, узор, ссылку и ставит «Улучшенный». Под номером подсказка:
  «Ищем в Telegram…» / «Найден Vice Cream #12323» / «В Telegram не найден,
  заполните вручную». Ключ последнего успешного поиска хранится в ref, чтобы
  записанное обратно каноническое имя не запускало второй запрос.
- Поля подарка переставлены: коллекция, номер, затем модель/фон/узор — номер
  вводится сразу после коллекции.
- `Portfolio.tsx`, редактор карточки: поле «Название» скрыто для подарков,
  название пересчитывается при сохранении; без коллекции остаётся прежнее.
- `.claude/launch.json`: конфигурация `backend-alt` на :8001 для случая,
  когда :8000 занят docker-стеком.

**Проверено в браузере (390px, тестовый аккаунт на локальной базе):**
`vice cream` + `12323` → поля `Unicone 3%`, `Chestnut 1.2%`, `Evil Dragon 0.3%`,
ссылка `https://t.me/nft/ViceCream-12323`, подсказка «Найден Vice Cream #12323»;
после создания плитка показывает картинку с fragment, карточка —
«Vice Cream #12323» и три признака с процентами. В редакторе поля названия
нет; смена номера на `1` даёт «Vice Cream #1». `Plush Pepe` + `99999999` →
«В Telegram не найден, заполните вручную». Ошибок в консоли нет.

## Откат

`git revert` коммитов ветки. Миграций нет; созданные с автоназванием позиции
остаются обычными позициями с текстовым `title`.

## Известные уязвимости / осознанные риски

- Сервер ходит на `t.me` по запросу пользователя. Параметры жёстко
  ограничены (хост фиксирован, slug и номер валидируются, редиректы
  выключены), так что через ручку нельзя запросить другой адрес. Лимита
  частоты нет: одна форма делает не больше одного запроса на пару
  «коллекция+номер» после паузы 500 мс.
- Значения с t.me сохраняются как обычный текст атрибутов и проходят
  `calc__collectible_metadata`; в DOM попадают только как текст.

**Поправлено самой сессией** (коммит `e88dd80`):

- Подсказка получила `role="status"`: результат поиска объявляется
  скринридером, иначе автозаполнение пяти полей проходило молча.
- «Ищу в Telegram…» → «Ищем в Telegram…» — как «Проверяем…/Отменяем…» в
  справочнике (§7), без первого лица единственного числа.
- Поле «Коллекция» получило `autoFocus` для подарка: раньше фокус при
  открытии получало скрытое теперь поле «Название», и шторка открывалась без
  фокуса (`after-form-light-focus.jpg`).

**Замечания автору (логика):**

1. **Устаревшие атрибуты после «не найден».** Сценарий: `Plush Pepe` + `1`
   (найден, поля заполнены) → меняем номер на `99999999` → «не найден», но
   модель/фон/узор, «Улучшенный» и ссылка `…/PlushPepe-1` остаются от
   первого подарка (`form-light-missing.jpg`). Позиция «Plush Pepe #99999999»
   создастся с чужими признаками и чужой ссылкой. Предложение: при ответе
   «не найден» очищать то, что подставил предыдущий успешный поиск (хотя бы
   ссылку, она гарантированно не совпадает с номером); ручной ввод при
   этом не страдает — он идёт после «не найден».
2. **Подсказка не возвращается в «найден».** `1` → найден → `99999999` → не
   найден → снова `1`: ключ совпадает с `giftLookedUp.current`, эффект
   выходит молча, и под полем остаётся «В Telegram не найден», хотя в полях
   значения #1. В ветке раннего выхода нужно ставить `setGiftLookup('found')`
   (или сбрасывать ref при смене ключа).
3. **Редактор карточки: номер меняется, ссылка нет.** У тестового предмета
   после правки номера `12323` → `1` название стало «Vice Cream #1», картинка
   берётся с fragment для `vicecream-1`, а ссылка «t.me» по-прежнему ведёт на
   `ViceCream-12323`. Автозапрос в редакторе вне задачи, но пересчитывать
   ссылку вместе с названием (если она была вида `https://t.me/nft/<slug>-<N>`)
   — одна строка рядом с `telegramGiftTitle`. Можно вынести в тот же
   открытый вопрос про «Обновить из Telegram».

Не по задаче (долг, в ветке не трогается): подписи `.apf-label` в этой форме
и в `.clx-editor` не связаны с полями через `htmlFor`/вложение, поэтому в
дереве доступности поля называются по плейсхолдеру («1234»,
«Необязательно»). Старое поведение всей формы, axe в `a11y.spec.ts` его не
ловит, потому что шторка в тестах не открывается.

Полный `scripts/check.sh` после правок — зелёный (браузерные тесты и
снимки не изменились: шторка новой позиции в них не открывается).

## Исправления после дизайн-ревью

Все три замечания по логике исправлены одним коммитом и проверены в браузере:

1. «Не найден» после успешного поиска очищает то, что подставил предыдущий
   поиск: модель, фон, узор, флаг «Улучшенный» и ссылку. Поля, введённые
   руками без предыдущего успешного поиска, не трогаются.
2. Возврат к уже найденной паре «коллекция+номер» снова показывает «Найден…»
   (ранний выход из эффекта ставит состояние `found`; после «не найден» ключ
   последнего успеха сбрасывается, и поиск повторяется).
3. Редактор карточки: `telegramGiftLink(attributes)` пересчитывает ссылку
   по коллекции и номеру, если прежняя ссылка пустая или ведёт на
   `https://t.me/nft/…`; ссылка на другой адрес остаётся пользовательской.
   Проверено: номер `1` → `12323` даёт «Vice Cream #12323» и ссылку
   `…/ViceCream-12323`.

Долг вне задачи (из дизайн-ревью): подписи `.apf-label` в форме позиции и в
`.clx-editor` не связаны с полями через `htmlFor`; в дереве доступности поля
называются по плейсхолдеру.
