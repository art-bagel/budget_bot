## Денежные сценарии и Bybit

В локальной `bybit_all_operations.csv` 1017 строк за 15.06.2024–06.09.2026.
Все 61 строки Fiat обозначены P2P Purchase, с заполненной рублёвой суммой.
Новый buy_fiat в базовой валюте RUB подходит по типу операции; ещё нужны
ресурсы бота, источник оплаченных рублей, время и порядок общего журнала.
Это лишь часть собственных вложений: сумма этой выгрузки не заменяет итог
всех источников, включая Telegram/server и более ранние приобретения.

Три продажи другу выделены из уточнения владельца от 19.09.2026: события
228, 258, 281. Взяты только дата, количество и фактическая выручка. Старые
расчётные поля себестоимости/прибыли из того же файла намеренно не перенесены.

194 строки TRADE образуют 78 групп по дате, минуте и счёту. 65 групп содержат
ровно две строки, 13 — несколько исполнений. После суммирования по активу
все 78 имеют один входящий и один исходящий актив; направления отдельных строк
не противоречат этой группировке. Это кандидаты обменов, не доказательство
единого ордера или правильного порядка между другими операциями той же минуты.
Во всех строках TRADE рублёвая сумма отсутствует. 42 строки не содержат деталей.
Исходные строки сохранены: нельзя повторно списать комиссию, уже включённую
в полученное/списанное количество, или перенести прежнюю стоимость вместо

Остальные важные типы: 424 Earn, 79 Bybit Card, 18 Deposit, 47 Withdraw,

возвратом займа. Все строки включены со статусом not_mapped.

## Где результат и как повторить

Локальный результат в рабочей криптоветке:
`outputs/crypto-history-inventory-2026-09-23-v2/`.

- summary.json — версии блоков, количества, проверки и SHA-256 входов;
- main-events.json — все исходные события с привязкой к номеру;
- main-movements.json — все движения и точные десятичные количества;
- bybit-rows.json — все строки выгрузки с исходным номером;
- bybit-fiat.json — рублёвые покупки;
- bybit-trade-groups.json — предварительные пары активов, количества и ссылки на строки;
- friend-sales.json — три подтверждённые продажи.

Файлы содержат личные данные и остаются в ignored outputs/, в Git добавлен
только сборщик и документация. Предыдущие материалы и результат первого
инвентаря сохранены. Сборщик отказывается перезаписывать существующий каталог
и писать личный результат вне outputs/.

```sh
python scripts/crypto/build_history_inventory.py \
  --source-ref 7b2663b \
  --bybit-csv /path/to/crypto-task/local-data/bybit_all_operations.csv \
  --output-dir outputs/crypto-history-inventory-new
```

Проверки полного фактического набора прошли; ruff сборщика/backend/storage и
проверка diff прошли. База, исходная CSV и принятые Excel не изменялись.

## Следующий ограниченный проход

1. Добавить извлечённые операции Telegram/server, привязки своих кошельков и
   Ethereum из прежнего разбора; не пересобирать старые доказательства с нуля.
2. Составить соответствие «строка источника → команда или объяснённое исключение».
   У каждой исходной строки должен остаться статус, даже если проводить её нельзя.
3. Отдельно проверить обычные займы другу без залога, Earn, подарки и LP —
   наличие похожего DeFi-метода не означает готовность каждого сценария.
4. Для обменов использовать подтверждённую историческую оценку или unknown.
   Не внедрять поддержку произвольных денежных валют без такого случая в истории.
5. После покрытия нужных типов — безопасный пересчёт исправленного журнала,
   затем полный dev-прогон по контрольным сотням.
